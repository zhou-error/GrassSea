## 概念讲解

### 一、为什么需要连接管理

**直接连接的问题**：

```python
# 错误示范：每次请求都创建新连接
@app.get("/users/{id}")
async def get_user(id: str):
    conn = await asyncpg.connect("postgresql://...")  # 建立连接（慢！）
    result = await conn.fetch("SELECT * FROM users WHERE id=$1", id)
    await conn.close()                                  # 关闭连接
    return result
```

每次 HTTP 请求都创建和销毁数据库连接，开销极大。建立一个 PostgreSQL 连接需要：
1. TCP 三次握手
2. SSL 握手（如果启用）
3. 认证（用户名/密码验证）
4. 数据库分配后端进程

整个过程可能需要 50-200ms，而实际查询可能只需要 5ms。

**连接池的解决方案**：

```
连接池 (Connection Pool)

请求1 ──┐                    ┌──────────────────┐
请求2 ──┤                    │   连接池 (Pool)    │      PostgreSQL
请求3 ──┼── 借连接 ────────> │  ┌──┐ ┌──┐ ┌──┐ │ ────> 数据库
请求4 ──┤                    │  │C1│ │C2│ │C3│ │
请求5 ──┘                    │  └──┘ └──┘ └──┘ │
                             │  20 个预建连接    │
                             └──────────────────┘

请求来时: 从池中借一个连接 (微秒级)
请求结束: 连接归还池中 (不销毁)
```

连接池在应用启动时创建一批连接，请求只是"借用"和"归还"，不需要反复建立和销毁。

### 二、SQLAlchemy 连接池的关键参数

```python
pg_engine = create_async_engine(
    settings.POSTGRES_URI,
    pool_size=20,          # 池中保持的连接数
    max_overflow=10,       # 池满时可额外创建的连接数
    pool_pre_ping=True,    # 使用前测试连接是否有效
    pool_recycle=3600,     # 连接最大存活时间（秒），防止内存泄漏
)
```

| 参数 | 含义 | GrassSea 值 | 生产建议 |
|------|------|------------|---------|
| `pool_size` | 常驻连接数 | 20 | 根据并发量调整 |
| `max_overflow` | 临时超额连接数 | 10 | pool_size + overflow = 最大连接数 |
| `pool_pre_ping` | 借出前检测有效性 | True | 必须开启（防止使用已断连接） |
| `pool_recycle` | 连接最大存活时间 | 默认 | 3600 秒（防止 PG 服务端断开） |

**连接耗尽与 back pressure**：

```
最大连接数 = pool_size + max_overflow = 20 + 10 = 30

如果同时有 31 个请求需要数据库连接：
- 前 30 个：获得连接，正常处理
- 第 31 个：排队等待（阻塞），直到有连接归还

如果设置了超时时间，超时后会抛出 TimeoutError。
```

### 三、多数据库协同管理

GrassSea 需要同时管理 4 种数据库连接，每种有不同的初始化方式：

```
应用启动 (lifespan)
│
├── PostgreSQL ── 引擎启动时创建连接池，无需显式 init
│
├── MongoDB ──── init_mongodb()  → 创建 AsyncIOMotorClient
│
├── Redis ────── init_redis()    → 创建 redis.asyncio.Redis
│
└── Milvus ───── init_milvus()   → connections.connect()
```

**为什么 PostgreSQL 不需要显式 init？**

SQLAlchemy 的 `create_async_engine` 创建的引擎是延迟连接的——连接池在第一次实际查询时才建立连接。而 MongoDB（Motor）、Redis、Milvus 的客户端需要显式调用连接方法。

## 项目代码精讲

### 第 1 段：PostgreSQL 连接管理

```python
pg_engine = create_async_engine(
    settings.POSTGRES_URI,
    echo=settings.APP_DEBUG,   # 开发模式输出 SQL
    pool_size=20,
    max_overflow=10,
    pool_pre_ping=True,
)

pg_session_factory = async_sessionmaker(
    pg_engine,
    class_=AsyncSession,
    expire_on_commit=False,    # 提交后不使对象过期
)
```

`async_sessionmaker` 是一个会话工厂——不是直接创建会话，而是创建一个"创建会话的工厂"。每次调用 `pg_session_factory()` 就生成一个新的 `AsyncSession`。

`expire_on_commit=False` 的意义：提交事务后，SQLAlchemy 默认会将所有对象标记为"过期"（下次访问属性时重新查询）。在异步环境中，这可能导致延迟加载错误。设为 False 避免这个问题。

#### FastAPI 依赖注入

```python
async def get_pg_session() -> AsyncGenerator[AsyncSession, None]:
    """获取 PostgreSQL 异步会话 (用于 FastAPI 依赖注入)"""
    async with pg_session_factory() as session:
        try:
            yield session
            await session.commit()    # 请求成功后提交
        except Exception:
            await session.rollback()  # 出错时回滚
            raise
```

**这个函数设计精妙**：

```
HTTP 请求生命周期:

1. 请求到达
2. FastAPI 调用 get_pg_session()
3. 创建 AsyncSession（从连接池借连接）
4. yield session → 传给路由函数
5. 路由函数执行业务逻辑（使用 session）
6. 路由函数返回响应
7. 回到 get_pg_session() 中
8. 如果正常：await session.commit()
9. 如果异常：await session.rollback()
10. async with 退出，session 关闭，连接归还池
```

在路由中使用：

```python
@app.get("/projects")
async def list_projects(session: AsyncSession = Depends(get_pg_session)):
    # get_pg_session 自动管理事务
    projects = await session.execute(select(Project))
    return projects.scalars().all()
    # 函数返回后，get_pg_session 自动 commit
```

### 第 2 段：MongoDB 连接管理

```python
mongo_client: AsyncIOMotorClient | None = None
mongo_db: AsyncIOMotorDatabase | None = None

async def init_mongodb() -> None:
    global mongo_client, mongo_db
    mongo_client = AsyncIOMotorClient(settings.MONGODB_URI)
    mongo_db = mongo_client[settings.MONGODB_DB]
    await mongo_client.admin.command("ping")  # 验证连接

async def close_mongodb() -> None:
    global mongo_client
    if mongo_client:
        mongo_client.close()
        mongo_client = None

def get_mongo_db() -> AsyncIOMotorDatabase:
    if mongo_db is None:
        raise RuntimeError("MongoDB not initialized. Call init_mongodb() first.")
    return mongo_db
```

MongoDB 的连接管理使用模块级全局变量 + 显式 init/close 模式。这与 PostgreSQL 不同——Motor 没有内置的连接池管理，需要手动管理客户端生命周期。

**初始化顺序很重要**：必须先 `init_mongodb()`，才能使用 `get_mongo_db()`。

### 第 3 段：Redis 连接管理

```python
redis_client: Redis | None = None

async def init_redis() -> None:
    global redis_client
    redis_client = Redis.from_url(
        settings.REDIS_URI,
        encoding="utf-8",
        decode_responses=True,  # 自动解码为 str
    )
    await redis_client.ping()

async def close_redis() -> None:
    global redis_client
    if redis_client:
        await redis_client.close()
        redis_client = None
```

结构与 MongoDB 类似，但 Redis 客户端自带连接池。

`decode_responses=True`：Redis 默认返回 bytes，设为 True 后自动解码为 str，减少手动 `.decode()` 的繁琐。

### 第 4 段：Milvus 连接管理

```python
from pymilvus import connections

def init_milvus() -> None:
    connections.connect(
        alias="default",
        host=settings.MILVUS_HOST,
        port=settings.MILVUS_PORT,
    )

def close_milvus() -> None:
    connections.disconnect("default")
```

注意：Milvus 的连接管理是**同步**的（不使用 async/await）。pymilvus 库目前主要通过 gRPC 连接，连接建立是同步操作。

### 应用生命周期中的数据库管理

在服务启动时初始化所有数据库：

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # === 启动阶段 ===
    await init_mongodb()
    await init_redis()
    init_milvus()
    logger.info("All databases initialized")

    yield  # 应用运行中

    # === 关闭阶段 ===
    await close_mongodb()
    await close_redis()
    close_milvus()
    logger.info("All databases closed")
```

## 手把手实践

### 任务：编写一个简化的连接管理模块

```python
# simple_db.py
from contextlib import asynccontextmanager
from motor.motor_asyncio import AsyncIOMotorClient
from redis.asyncio import Redis
from sqlalchemy.ext.asyncio import create_async_engine, async_sessionmaker, AsyncSession

# PostgreSQL
engine = create_async_engine("postgresql+asyncpg://user:pass@localhost:5432/db")
SessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

# MongoDB（全局变量 + 显式 init）
mongo_client = None

async def init_mongo(uri: str):
    global mongo_client
    mongo_client = AsyncIOMotorClient(uri)
    await mongo_client.admin.command("ping")
    print("MongoDB connected")

# Redis（全局变量 + 显式 init）
redis_client = None

async def init_redis(uri: str):
    global redis_client
    redis_client = Redis.from_url(uri, decode_responses=True)
    await redis_client.ping()
    print("Redis connected")

# 依赖注入
async def get_pg_session():
    async with SessionLocal() as session:
        yield session

# 应用生命周期
@asynccontextmanager
async def lifespan(app):
    await init_mongo("mongodb://localhost:27017")
    await init_redis("redis://localhost:6379")
    yield
    if mongo_client:
        mongo_client.close()
    if redis_client:
        await redis_client.close()
```

## 常见问题与排错

### Q1: `RuntimeError: MongoDB not initialized`
**原因**：在应用启动前或关闭后调用了 `get_mongo_db()`。
**解决**：检查初始化顺序，确保在 FastAPI 的 `lifespan` 中初始化了所有数据库。

### Q2: 连接池耗尽 `QueuePool limit of size 20 overflow 10 reached`
**原因**：并发请求数超过了最大连接数（30）。
**解决**：
- 增大 `pool_size` 和 `max_overflow`
- 检查是否有慢查询占用连接
- 检查是否忘记关闭 session（`async with` 是必须的）

### Q3: `connection was closed in the middle of operation`
**原因**：PostgreSQL 服务端关闭了空闲连接，但客户端不知道。
**解决**：设置 `pool_pre_ping=True`，SQLAlchemy 在借出连接前发送 `SELECT 1` 验证连接有效性。

### Q4: 多个服务如何共享 Redis/Mongo 连接？
每个 FastAPI 应用实例有自己的一组连接。在微服务架构中，每个服务独立管理自己的数据库连接——它们不共享连接池。但可以共享同一个数据库服务器。
