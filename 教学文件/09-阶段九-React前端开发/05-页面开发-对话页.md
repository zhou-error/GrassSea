## 项目代码精讲

**文件位置**: `frontend/src/pages/Chat.tsx`

### 1. 组件状态与初始化

```typescript
const ChatPage: React.FC = () => {
  const { messages, sessionId, streaming, addMessage, appendContent,
          setSessionId, setStreaming } = useChatStore();
  const [input, setInput] = useState('');
  const messagesEndRef = useRef<HTMLDivElement>(null);
```

**逐段解析**：

1. `useChatStore()` — 从 Zustand Store 中"解构"出所需的状态和方法。`useChatStore()` 不带选择器参数时获取整个 Store，但这里通过解构只取需要的部分。

2. `const [input, setInput] = useState('');` — 输入框的本地状态。`input` 只在这个组件中使用，不需要放入全局 Store。

3. `useRef<HTMLDivElement>(null)` — 创建一个 ref 引用，指向消息列表底部的"锚点 div"。用于自动滚动到最新消息。泛型 `<HTMLDivElement>` 告诉 TypeScript 这是一个 div 元素。

### 2. 自动滚动

```typescript
useEffect(() => {
  messagesEndRef.current?.scrollIntoView({ behavior: 'smooth' });
}, [messages]);
```

**精讲**：

- `useEffect(..., [messages])` — 当 `messages` 数组变化时触发（新消息到达或内容追加）
- `scrollIntoView({ behavior: 'smooth' })` — 平滑滚动到锚点元素。`'smooth'` 产生动画效果，`'auto'` 则是瞬间跳转
- `?.` — TypeScript 的"可选链"语法。如果 `messagesEndRef.current` 是 `null`，不会报错，直接跳过

这个效果让用户在收到新消息时自动看到最新内容，无需手动拖动滚动条。

### 3. 发送消息（核心流程）

```typescript
const sendMessage = async () => {
  if (!input.trim() || streaming) return;

  // 1. 添加用户消息
  const userMsg = {
    id: `u_${Date.now()}`,
    role: 'user' as const,
    content: input.trim(),
    timestamp: Date.now()
  };
  addMessage(userMsg);
  const currentInput = input.trim();
  setInput('');
  setStreaming(true);

  // 2. 添加空的 AI 消息占位
  const assistantId = `a_${Date.now()}`;
  addMessage({
    id: assistantId,
    role: 'assistant',
    content: '',
    timestamp: Date.now()
  });
```

**逐步拆解**：

1. `if (!input.trim() || streaming) return;` — 空白消息或已在流式接收时不发送。`trim()` 去掉首尾空格。

2. `const userMsg = { id: `u_${Date.now()}`, ... }` — 生成用户消息。`u_` 前缀区分用户消息，`Date.now()` 作为唯一 ID（同一毫秒内多次调用理论上会冲突，但实际聊天场景间隔远大于 1ms）。

3. `addMessage(userMsg)` — 将用户消息加入 Store，触发重渲染，用户立刻看到自己的消息。

4. `setInput('')` — 清空输入框。

5. `setStreaming(true)` — 设置流式状态，禁用发送按钮。

6. 创建一个 `role: 'assistant'` 的空消息占位，`content: ''` 初始为空字符串。

### 4. 流式接收 AI 回复

```typescript
  // 3. 发送请求
  try {
    const res = await chatApi(currentInput, sessionId || undefined);
    const { session_id, answer, task_id, sources } = res.data;

    if (session_id) setSessionId(session_id);

    // 4. 逐字追加内容（模拟流式效果）
    for (const char of answer) {
      appendContent(assistantId, char);
      await new Promise((r) => setTimeout(r, 12));
    }

    // 5. 追加任务 ID
    if (task_id) {
      appendContent(assistantId, `\n\n> 任务ID: \`${task_id}\``);
    }
  } catch {
    appendContent(assistantId, '抱歉，服务暂时不可用。');
  } finally {
    setStreaming(false);
  }
};
```

**代码精讲 — 流式输出的核心逻辑**：

```typescript
for (const char of answer) {
  appendContent(assistantId, char);       // 每次追加一个字符
  await new Promise((r) => setTimeout(r, 12)); // 等待 12ms
}
```

这是一个"伪流式"效果——后端返回的是完整回答，前端逐字展示。真正的流式是后端通过 SSE (Server-Sent Events) 或 WebSocket 逐片推送。但对于教学阶段，"伪流式"效果足够好且简单。

为什么是 12ms？12ms 对应约 83 字符/秒，是舒适的阅读速度。中文阅读速度约 300-500 字/分钟（5-8 字/秒），12ms/字符稍快但配合 Markdown 渲染的视觉节奏正好。

**Markdown 中的任务 ID**：

```typescript
appendContent(assistantId, `\n\n> 任务ID: \`${task_id}\``);
```

`\n\n> ` 在 Markdown 中产生一个引用块（blockquote），`` `...` `` 产生行内代码样式。最终渲染效果：

> 任务ID: `abc12345`

**错误处理**：

```typescript
} catch {
  appendContent(assistantId, '抱歉，服务暂时不可用。');
} finally {
  setStreaming(false);
}
```

`catch` 块显示错误提示，`finally` 块确保无论如何都会解除流式状态。这样即使请求失败，发送按钮也能恢复可用。

### 5. CapsuleTag 胶囊标签组件

```typescript
const CapsuleTag: React.FC<{ label: string }> = ({ label }) => (
  <span
    style={{
      display: 'inline-block',
      padding: '4px 14px',
      margin: '3px 4px',
      background: 'rgba(193,213,192,0.28)',
      color: '#2D3A30',
      borderRadius: 20,
      fontSize: 11.5,
      fontWeight: 500,
      letterSpacing: '0.02em',
      cursor: 'pointer',
      transition: 'var(--transition)',
      animation: 'floatUp 3s ease-in-out infinite',
    }}
    onMouseEnter={(e) => {
      (e.target as HTMLElement).style.transform = 'translateY(-2px)';
    }}
    onMouseLeave={(e) => {
      (e.target as HTMLElement).style.transform = 'translateY(0)';
    }}
  >
    {label}
  </span>
);
```

**代码精讲**：

这是一个**局部组件**（定义在 Chat.tsx 文件内，不单独导出），只在空状态引导区域使用。

- `React.FC<{ label: string }>` — 泛型标注 props 类型。`{ label: string }` 表示接受一个 `label` 字符串属性。
- `animation: 'floatUp 3s ease-in-out infinite'` — 使用 index.css 中定义的全局动画，标签会上下浮动（3秒周期，无限循环）。
- `onMouseEnter / onMouseLeave` — 鼠标悬停时上浮 2px。直接操作 DOM style 而非 React state，避免不必要的重渲染。

### 6. 聊天气泡

```typescript
{messages.map((msg) => (
  <div
    key={msg.id}
    style={{
      display: 'flex',
      flexDirection: msg.role === 'user' ? 'row-reverse' : 'row',
      gap: 10,
      marginBottom: 18,
      animation: 'fadeIn 0.3s ease-out',
    }}
  >
    <div style={{
      maxWidth: '72%',
      padding: '14px 20px',
      borderRadius: msg.role === 'user'
        ? 'var(--radius-lg) 4px var(--radius-lg) var(--radius-lg)'
        : '4px var(--radius-lg) var(--radius-lg) var(--radius-lg)',
      background: msg.role === 'user'
        ? 'var(--bubble-right)' : 'var(--bubble-left)',
      boxShadow: 'var(--shadow-soft)',
    }}>
```

**气泡设计精讲**：

1. `flexDirection: ... 'row-reverse' : 'row'` — 用户消息用 `row-reverse`（右对齐），AI 消息用 `row`（左对齐）。

2. `maxWidth: '72%'` — 消息最大宽度 72%。短消息不会占满整行，保持"聊天气泡"的视觉感。

3. **不对称圆角**：

```
用户消息 (右):  左上圆角22px  右上尖角4px  右下圆角22px  左下圆角22px
AI消息  (左):   左上尖角4px   右上圆角22px 右下圆角22px  左下圆角22px
```

尖角指向说话者（用户的气泡尖角在右上，AI 的气泡尖角在左上），这是经典聊天气泡设计手法。

4. `background: ... 'var(--bubble-right)' : 'var(--bubble-left)'` — 用户和 AI 使用不同的背景色（淡蓝 vs 淡绿），形成视觉区分。

### 7. Markdown 渲染

```typescript
<div className="markdown-body" style={{ fontSize: '13.5px', lineHeight: 1.75 }}>
  <ReactMarkdown remarkPlugins={[remarkGfm]}>
    {msg.content || (streaming ? '...' : '')}
  </ReactMarkdown>
</div>
```

**代码精讲**：

- `className="markdown-body"` — 使用 GitHub 风格的 Markdown 样式类名。这是约定俗成的类名，很多 Markdown CSS 主题都基于它。
- `<ReactMarkdown remarkPlugins={[remarkGfm]}>` — 启用 GFM (GitHub Flavored Markdown) 插件，支持表格、删除线、任务列表等扩展语法。
- `{msg.content || (streaming ? '...' : '')}` — 显示内容。如果流式过程中 content 还是空字符串且 streaming 为 true，显示 `...` 占位。

**时间戳样式**：

```typescript
<div style={{
  fontSize: 10,
  color: 'var(--text-muted)',
  marginTop: 6,
  textAlign: 'right'
}}>
  {dayjs(msg.timestamp).format('HH:mm')}
</div>
```

`dayjs(msg.timestamp).format('HH:mm')` 将 Unix 时间戳格式化为 `时:分`（如 `14:35`）。dayjs 的 API 与 moment.js 完全兼容，但体积只有 2KB。

### 8. 输入区

```typescript
<Input.TextArea
  value={input}
  onChange={(e) => setInput(e.target.value)}
  onPressEnter={(e) => {
    if (!e.shiftKey) { e.preventDefault(); sendMessage(); }
  }}
  placeholder="输入工程问题，Enter 发送，Shift+Enter 换行..."
  autoSize={{ minRows: 1, maxRows: 4 }}
  disabled={streaming}
/>
```

**输入区设计精讲**：

1. `onPressEnter` — **关键交互设计**。Enter 发送，Shift+Enter 换行。`e.shiftKey` 检测是否按住了 Shift 键。`e.preventDefault()` 阻止默认的换行行为。

2. `autoSize={{ minRows: 1, maxRows: 4 }}` — Ant Design 的 TextArea 自动调整高度，最小 1 行，最大 4 行。超过 4 行后内部出现滚动条。

3. `disabled={streaming}` — 流式接收期间禁用输入，防止用户在 AI 回复中插入新消息。

4. **发送按钮状态**：流式期间按钮变灰 + cursor 变为 `not-allowed`，视觉上告知用户"正在等待回复"。

将 `setTimeout(r, 12)` 改为 `setTimeout(r, 50)`，观察打字速度明显变慢。再改为 `setTimeout(r, 3)`，观察打字速度飞快。

找到你觉得最舒适的阅读速度。

### 实践3: 添加代码块语法高亮

在 `<ReactMarkdown>` 中添加 `components` 属性实现代码高亮：

```typescript
import { Prism as SyntaxHighlighter } from 'react-syntax-highlighter';

<ReactMarkdown
  remarkPlugins={[remarkGfm]}
  components={{
    code({ node, className, children, ...props }) {
      const match = /language-(\w+)/.exec(className || '');
      return match ? (
        <SyntaxHighlighter language={match[1]} PreTag="div">
          {String(children).replace(/\n$/, '')}
        </SyntaxHighlighter>
      ) : (
        <code className={className} {...props}>{children}</code>
      );
    }
  }}

  {msg.content}
</ReactMarkdown>
```

## 常见问题与排错

### Q1: 消息不自动滚动到最新

**检查**:
1. `messagesEndRef` 是否正确附加到列表底部的 `div`
2. `useEffect` 的依赖数组是否包含 `messages`
3. 如果消息内容通过追加方式变化（`appendContent`），确认 `messages` 数组引用是否真的变了（Zustand 的 `set` 方法创建新数组）

### Q2: Markdown 表格不显示

**原因**: 未启用 GFM（GitHub Flavored Markdown）插件。
**解决**: 确认 `<ReactMarkdown remarkPlugins={[remarkGfm]}>` 中的 `remarkGfm` 已导入并传入。

### Q3: 中文输入时 Enter 误发送

**原因**: 中文输入法在选词阶段也会触发 Enter 事件。
**解决**: 使用 `onPressEnter` 时增加 IME 检测。Ant Design 的 `Input.TextArea` 已经处理了这个问题——只有当输入法组合结束（`compositionend`）后按 Enter 才会触发。

### Q4: 输入框在长时间对话后变卡

**原因**: 大量消息的 DOM 节点没有卸载。
**解决方案**: 使用虚拟滚动（react-window / react-virtuoso）渲染消息列表，保持 DOM 节点数量恒定。
