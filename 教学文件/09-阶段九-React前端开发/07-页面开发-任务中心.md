## 概念讲解

### TaskCenter 与 DAGPanel 的协作

```
+------------------------------------------+------------+
|  TaskCenter (左侧 flex: 1)               | DAGPanel   |
|                                           | (280px)   |
|  任务列表                                  |            |
|  +--------------------------------------+  |  拓扑图    |
|  | ● 稳性计算与报告生成         已完成 |  |            |
|  | [████████████████████████] 100%    |  |  DAG      |
|  | naval_arch_agent        10:30     |  |  / \      |
|  +--------------------------------------+  | DAG DAG   |
|  |                                   |  |  \ /      |
|  | ● 散货船型线设计优化        运行中  |  |  DAG      |
|  | [████████░░░░░░░░░░░░░░░░] 42%   |  |   |       |
|  | pm_agent                 10:38     |  |  File     |
|  +--------------------------------------+  |            |
+------------------------------------------+------------+
```

两个组件同属一个父容器（Chat.tsx 的三栏布局），但职责独立：
- `TaskCenter` — 任务列表管理
- `DAGPanel` — 任务依赖关系可视化

### 任务状态机

```
pending (等待中)  -->  running (运行中)  -->  completed (已完成)
                            |
                            v
                        failed (失败)
```

四种状态各有独特的视觉编码：

| 状态 | 圆点颜色 | 标签颜色 | 背景色 |
|------|---------|---------|--------|
| completed | 绿色 #7DBB8A | 深绿 #3D5A3F | 淡绿 rgba |
| running | 蓝色 #7BB5D0 | 深蓝 #3D5A5F | 淡蓝 rgba |
| pending | 灰色 #ccc | 灰色 #888 | 淡灰 rgba |
| failed | 红色 #E06C6C | 暗红 #8B3A3A | 淡红 rgba |

## 项目代码精讲

### 1. TaskCenter — 任务列表

**文件位置**: `frontend/src/pages/TaskCenter.tsx`

#### 状态样式映射

```typescript
const statusStyle: Record<string, { bg: string; color: string; dot: string }> = {
  completed: { bg: 'rgba(125,187,138,0.10)', color: '#3D5A3F', dot: 'var(--status-green)' },
  running:   { bg: 'rgba(181,214,224,0.12)', color: '#3D5A5F', dot: '#7BB5D0' },
  pending:   { bg: 'rgba(0,0,0,0.03)',       color: '#888',    dot: '#ccc' },
  failed:    { bg: 'rgba(224,108,108,0.08)', color: '#8B3A3A', dot: '#E06C6C' },
};
```

**代码精讲**：

这是一个"查表法"的实现模式——通过任务状态直接索引到对应的样式配置，避免了大量的 if-else 或 switch 语句。代码简洁且易于扩展（新增状态只需加一条映射）。

```typescript
const st = statusStyle[task.status] || statusStyle.pending;
```

当 `task.status` 不在映射表中时，回退到 `pending` 样式。这是防御性编程——即使数据出现意外的状态值，UI 也不会崩溃。

#### 模拟任务数据

```typescript
const dummyTasks = [
  {
    id: '1',
    title: '稳性计算与报告生成',
    type: '专业任务',      // 任务类型
    status: 'completed',
    progress: 100,
    agent: 'naval_arch_agent',  // 执行智能体
    time: '10:30'
  },
  // ...
];
```

`agent` 字段使用了下划线命名（`naval_arch_agent`），这是从后端 Python 服务返回的字段。前端在展示时用 `.mono` 等宽字体渲染，形成"技术代码"的视觉风格。

#### 进度条渐变配置

```typescript
<Progress
  percent={task.progress}
  size="small"
  showInfo={false}
  strokeColor={{
    '0%': '#B5D6E0',    // 起点：冰川蓝
    '100%': '#C1D5C0',  // 终点：鼠尾草绿
  }}
  trailColor="rgba(0,0,0,0.04)"
/>
```

**代码精讲**：

- `strokeColor` 接受**渐变对象**而非单一颜色。`'0%'` 到 `'100%'` 创建从左到右的颜色渐变——从冰川蓝过渡到鼠尾草绿。这种渐变色不在标准 Ant Design 文档的显眼位置，但它完全支持。

- `trailColor="rgba(0,0,0,0.04)"` — 未完成部分的颜色。4% 不透明度的黑色，几乎看不见但提供了视觉"轨道"。

- `showInfo={false}` — 隐藏百分数字。百分比信息通过进度条长度直观表达，不需要再显示数字。

- `size="small"` — 细条进度条（4px 高），适合紧凑的任务列表。

#### 运行中任务的背景高亮

```typescript
style={{
  background: task.status === 'running'
    ? 'rgba(181,214,224,0.04)'
    : 'transparent',
  transition: 'var(--transition)',
}}
```

运行中的任务有淡蓝色背景（4% 不透明度），而非运行任务保持透明。这让用户一眼就能找到"正在执行"的任务。

#### 智能体标签

```typescript
<span className="mono" style={{ fontSize: 11 }}>
  {task.agent}
</span>
```

使用 `.mono` 类（等宽字体）显示智能体名称。等宽字体让技术标识看起来更像"代码"或"命令行"，这是开发者工具 UI 的常见手法。

### 2. DAGPanel — 任务拓扑可视化

**文件位置**: `frontend/src/components/DAGPanel.tsx`

#### 数据模型

```typescript
interface DAGNode {
  id: string;
  label: string;
  x: number;
  y: number;
  deps: string[];     // 依赖的节点 ID 列表
}

const dagNodes: DAGNode[] = [
  { id: 'n1', label: 'DAG',  x: 140, y: 40,  deps: [] },
  { id: 'n2', label: 'DAG',  x: 60,  y: 120, deps: ['n1'] },
  { id: 'n3', label: 'DAG',  x: 220, y: 120, deps: ['n1'] },
  { id: 'n4', label: 'DAG',  x: 140, y: 200, deps: ['n2', 'n3'] },
  { id: 'n5', label: 'File', x: 140, y: 280, deps: ['n4'] },
];
```

**DAG 结构可视化**：

```
         n1 (根节点)
        /        \
      n2          n3    (并行组)
        \        /
         n4              (汇聚节点)
          |
         n5 (File)       (终端节点)
```

这是一个典型的"分发-处理-汇聚"任务流：
- n1 是入口任务，分解为 n2 和 n3 并行执行
- n2 和 n3 都完成后，n4 汇总结果
- n5 是最终输出（文件）

#### 连接线绘制

```typescript
{dagNodes.map((node) =>
  node.deps.map((depId) => {
    const dep = dagNodes.find((n) => n.id === depId);
    if (!dep) return null;
    return (
      <line
        key={`${depId}-${node.id}`}
        x1={dep.x} y1={dep.y + 20}
        x2={node.x} y2={node.y - 6}
        stroke="#C1D5C0"
        strokeWidth={1.2}
        strokeDasharray="4 3"
        opacity={0.7}
      />
    );
  })
)}
```

**代码精讲**：

1. `dep.y + 20` — 从依赖节点的**下方**（节点中心 + 20px）出发
2. `node.y - 6` — 到达目标节点的**上方**（节点中心 - 6px）
3. `strokeDasharray="4 3"` — 虚线样式：4px 实线 + 3px 空白交替
4. `stroke="#C1D5C0"` — 使用鼠尾草绿，与设计系统一致

这种"上到下"的有向连接线，清晰地表达了任务的执行顺序和依赖关系。

#### 节点渲染（SVG g 元素）

```typescript
{dagNodes.map((node) => (
  <g
    key={node.id}
    onMouseEnter={() => setHovered(node.id)}
    onMouseLeave={() => setHovered(null)}
    transform={hovered === node.id
      ? `translate(${node.x}, ${node.y - 2})`
      : `translate(${node.x}, ${node.y})`
    }
  >
    {/* 悬停光晕 */}
    {hovered === node.id && (
      <circle cx={0} cy={0} r={22} fill="rgba(181,214,224,0.18)" />
    )}

    {/* 节点圆 */}
    <circle
      cx={0} cy={0} r={16}
      fill="var(--bg-white)"
      stroke="var(--accent-glacier)"
      strokeWidth={1.2}
    />

    {/* 标签 */}
    <text
      y={-24}
      textAnchor="middle"
      fill={node.label === 'File' ? 'var(--text-secondary)' : 'var(--text-primary)'}
      fontSize={10}
      fontWeight={500}
    >
      {node.label}
    </text>
  </g>
))}
```

**精讲 SVG 变换**：

```typescript
transform={`translate(${node.x}, ${node.y})`}
```

SVG 的坐标系：原点在左上角，x 轴向右，y 轴向下。`translate(x, y)` 将节点移动到指定坐标。在 `<g>` 上设置 `transform` 后，内部元素的坐标是相对于 `<g>` 的。

**悬停效果**：

```typescript
transform={hovered === node.id
  ? `translate(${node.x}, ${node.y - 2})`
  : `translate(${node.x}, ${node.y})`
}
```

鼠标悬停时节点上浮 2px。这是通过变换实现的——不是通过 CSS 动画，而是通过 React state 切换 `transform` 值。简单但有效。

**终端节点特殊样式**：

```typescript
fill={node.label === 'File' ? 'var(--text-secondary)' : 'var(--text-primary)'}
```

最后一个节点（File）使用次要文字色（灰色），区别于上游的 DAG 节点。这是一种"视觉降权"——让终端输出节点不那么抢眼，突出上游的核心处理流程。

#### SVG viewBox

```typescript
<svg width="100%" height="340" viewBox="0 0 280 340" style={{ flex: 1 }}>
```

`viewBox="0 0 280 340"` 定义了 SVG 的可视区域：从 (0,0) 开始，宽 280，高 340。SVG 内部坐标在这个范围内，然后缩放到 `width="100%"` 的实际尺寸。

## 常见问题与排错

### Q1: SVG 连接线位置错乱

**原因**: `viewBox` 与实际元素坐标不匹配。
**排查**: 确认 `viewBox` 的宽度和高度 >= 所有节点的最大坐标值。当前节点最右是 n3 (x=220, r=16)，最下是 n5 (y=280)，都在 280x340 范围内。

### Q2: 进度条不更新

**原因**: 直接修改了 `dummyTasks` 数组而没有触发重渲染。
**解决**: 使用 `useState` 管理任务列表，通过 `setTasks()` 更新触发重渲染。

### Q3: 任务状态标签中文显示不统一

前端代码中将英文状态映射为中文显示：

```typescript
{task.status === 'completed' ? '已完成'
 : task.status === 'running' ? '运行中'
 : '等待中'}
```

确保新增状态时同步更新映射逻辑。

### Q4: DAG 面板的节点拖拽不工作

**原因**: 当前 DAGPanel 使用硬编码坐标，不支持拖拽。
**实现方案**: 添加 `onMouseDown` / `onMouseMove` / `onMouseUp` 事件监听，动态更新节点坐标。对于教学阶段，固定布局已足够清晰。
