## 概念讲解

### 知识库页面的设计目标

知识库页面是用户管理文档的中心。它需要支持三个核心功能：

```
+--------------------------------------------------+
|  知识库                                     [上传文档]│
|  管理规范标准、船舶设计、学术文献等知识资源         │
|                                                    │
|  [搜索文件... 🔍]                                  │
|                                                    │
|  📄 CCS钢质海船入级规范2024.pdf                     │
|     12.5 MB · 2026-07-03   [规范标准库] ● 已索引   │
|                                                    │
|  📊 散货船型值表_v2.xlsx                            │
|     856 KB · 2026-07-04    [项目知识库] ● 已索引   │
|                                                    │
|  📄 SOLAS_Consolidated_2024.pdf                     │
|     8.2 MB · 2026-07-04    [规范标准库] ● 索引中   │
|                                                    │
|  ...                                               │
+--------------------------------------------------+
```

每个文件行包含 6 种信息：
1. 文件图标（按类型映射）
2. 文件名（主信息）
3. 文件大小 + 日期（辅助信息）
4. 知识库分类标签（胶囊形 Tag）
5. 索引状态指示灯（圆点 + 文字）

## 项目代码精讲

**文件位置**: `frontend/src/pages/KnowledgeBase.tsx`

### 1. 文件类型图标映射

```typescript
const iconMap: Record<string, React.ReactNode> = {
  pdf: <FilePdfOutlined style={{ color: '#E06C6C', fontSize: 18 }} />,
  txt: <FileTextOutlined style={{ color: 'var(--accent-glacier)', fontSize: 18 }} />,
  md:  <FileTextOutlined style={{ color: 'var(--accent-sage)', fontSize: 18 }} />,
};
```

**代码精讲**：

- `Record<string, React.ReactNode>` — TypeScript 类型。`Record<K, V>` 表示"键为 string，值为 React 节点的对象"。这是一个类型安全的映射表。

- `FilePdfOutlined` — Ant Design Icons 提供的 PDF 图标，红色（`#E06C6C` = 砖红，传统的 PDF 色）。

- 三种文档类型各有一种颜色：PDF=红、TXT=冰川蓝、MD=鼠尾草绿。颜色与功能形成关联记忆。

### 2. 模拟数据

```typescript
const dummyFiles = [
  {

    name: 'CCS钢质海船入级规范2024.pdf',
    size: '12.5 MB',

```

**数据字段解析**：

| 字段 | 说明 | 用途 |
|------|------|------|
| key | 唯一标识 | React 列表渲染的 key 属性 |
| name | 文件名 | 列表主文字 |
| size | 格式化大小 | 显示 "12.5 MB" 而非原始字节 |
| type | 文件类型 | 决定图标（pdf/xlsx/md/txt） |
| kb | 知识库名 | Tag 标签显示 |
| status | 索引状态 | 状态圆点颜色 + 文字 |
| date | 日期 | 辅助信息 |

数据是硬编码的（`dummyFiles`）而非从 API 获取，表明当前处于前端开发阶段。

### 3. 文件上传处理

```typescript
const handleUpload = async (file: File) => {
  try {
    await uploadDocumentApi(file, '项目知识库');
    message.success(`${file.name} 上传成功`);
  } catch {
    message.error('上传失败');
  }
  return false;  // 阻止默认上传行为
};
```

**代码精讲**：

- `file: File` — 浏览器的原生 File 对象。`Upload` 组件的 `beforeUpload` 回调会传入这个对象。
- `'项目知识库'` — 硬编码的知识库名。后续会改为下拉选择。
- `message.success()` / `message.error()` — Ant Design 的全局消息提示，轻量级的"操作成功/失败"反馈。
- `return false` — **关键**。返回 `false` 阻止 Upload 组件的默认上传行为（Ant Design 默认会自动发送 POST 请求），改用自己的 `uploadDocumentApi` 手动上传。

### 4. Upload 按钮

```typescript
<Upload beforeUpload={handleUpload as any} showUploadList={false}>
  <button style={{
    height: 36,
    padding: '0 18px',
    border: '1px solid var(--accent-sage)',
    borderRadius: 'var(--radius-md)',
    background: 'rgba(193,213,192,0.10)',
    color: '#3D5A45',
    fontSize: 13,
    fontWeight: 500,
    cursor: 'pointer',
    display: 'flex',
    alignItems: 'center',
    gap: 6,
  }}>
    <UploadOutlined /> 上传文档
  </button>
</Upload>
```

**代码精讲**：

- `beforeUpload={handleUpload as any}` — TypeScript 类型断言 `as any`。`beforeUpload` 期望 `(file, fileList) => boolean | Promise<...>`，而 `handleUpload` 的签名是 `(file: File) => ...`，参数不完全匹配。用 `as any` 绕过类型检查（优先保证功能正确，后续完善类型）。

- `showUploadList={false}` — 不显示 Ant Design 默认的文件列表 UI，因为我们在下方自定义了文件列表。

- 按钮样式完全自定义（覆盖 Ant Design 的默认按钮样式），使用 inline style 而非 CSS 类——与项目整体风格一致。

### 5. 搜索过滤

```typescript
const [search, setSearch] = useState('');

// 过滤逻辑
{dummyFiles
  .filter((f) => !search || f.name.includes(search))
  .map((file) => ( ... ))}
```

**代码精讲**：

`!search || f.name.includes(search)` — 逻辑或：
- `!search` 为 true（搜索框为空） -> 不过滤，显示全部
- `search` 不为空 -> 用 `includes` 过滤（子串匹配）

这是最简单有效的客户端过滤方式。注意 `includes` 区分大小写——中文文件名没有大小写问题，英文文件名则可以改为 `f.name.toLowerCase().includes(search.toLowerCase())`。

### 6. 文件行悬停效果

```typescript
onMouseEnter={(e) => {
  (e.currentTarget as HTMLElement).style.background = 'rgba(193,213,192,0.06)';
}}
onMouseLeave={(e) => {
  (e.currentTarget as HTMLElement).style.background = 'transparent';
}}
```

**代码精讲**：

- `e.currentTarget` — 事件绑定的元素（即被遍历的文件行 `div`）。注意不是 `e.target`（事件实际触发的元素，可能是内部子元素）。
- `as HTMLElement` — TypeScript 类型断言。`e.currentTarget` 的默认类型是 `EventTarget`，没有 `style` 属性，断言为 `HTMLElement` 后可以访问 `style`。
- 直接操作 DOM style（不通过 React state）——避免每次鼠标移动都触发整个列表重渲染。这是性能优化的常用手法。

### 7. 状态指示灯与 Tag

```typescript
{/* 知识库 Tag */}
<Tag style={{
  background: 'rgba(193,213,192,0.18)',
  border: 'none',
  color: '#3D5A45',
  borderRadius: 20,
  fontSize: 11,
}}>
  {file.kb}
</Tag>

{/* 状态指示灯 */}
<div style={{
  width: 7, height: 7, borderRadius: '50%',
  background: file.status === '已索引'
    ? 'var(--status-green)' : '#D4A853',  // 绿色 vs 琥珀色
}} />
<span>{file.status}</span>
```

状态指示灯的设计：
- 绿色（`#7DBB8A`）= 已索引 = 可用
- 琥珀色（`#D4A853`）= 索引中 = 处理中

这种"颜色编码"让用户无需阅读文字就能快速判断文件状态。

## 常见问题与排错

### Q1: `beforeUpload` 类型报错

**错误**: `Type '(file: File) => Promise<void>' is not assignable to type...`
**临时方案**: 使用 `beforeUpload={handleUpload as any}` 绕过。
**正式方案**: 修改函数签名为 `(file: RcFile, fileList: RcFile[]) => Promise<...>` 或 `boolean`。

### Q2: 文件上传后不刷新列表

**原因**: 列表数据是静态的 `dummyFiles`，上传成功后没有重新加载。
**解决**: 使用 `useState` 管理文件列表，上传成功后调用 API 重新获取列表，或手动将新文件加入 state。

### Q3: 图标在某些类型文件上不显示

**原因**: 文件类型不在 `iconMap` 中。
**解决**: 在 JSX 中使用后备图标：

```typescript
{iconMap[file.type] || <FileTextOutlined style={{ fontSize: 18, color: 'var(--text-muted)' }} />}
```

### Q4: 搜索过滤区分大小写

**原因**: `String.includes()` 区分大小写。
**解决**: 统一转为小写：`f.name.toLowerCase().includes(search.toLowerCase())`
