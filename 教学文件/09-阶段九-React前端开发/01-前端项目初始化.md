## 概念讲解

### GrassSea 前端技术栈一览

```
+--------------------------------------------------------+
|  GrassSea Frontend 技术栈                               |
|                                                         |
|  构建工具:    Vite 5.x    (快速开发服务器 + 打包)       |
|  UI 框架:    React 18.x  (组件化视图)                   |
|  UI 组件库:  Ant Design 5.x (企业级组件)                |
|  路由:       React Router 6.x (SPA 页面导航)            |
|  状态管理:   Zustand 4.x  (轻量全局状态)                |
|  数据请求:   Axios 1.6    (HTTP 客户端)                 |
|  服务端缓存: TanStack Query 5.x (请求缓存 + 自动刷新)   |
|  Markdown:   react-markdown 9.x (Markdown 渲染)         |
|  类型系统:   TypeScript 5.x (类型安全)                  |
+--------------------------------------------------------+
```

这个技术栈选择体现了"不多不少"的原则：
- Vite 取代了老旧的 Webpack，开发体验更快
- Ant Design 提供了成熟的企业级 UI 组件，不用从零写表单/表格/弹窗
- Zustand 取代了 Redux，减少大量样板代码
- TanStack React Query 处理服务端缓存，避免手动管理 loading/error 状态

### 项目目录结构

```
frontend/
  |
  +-- package.json          # 依赖管理 + 脚本命令
  +-- vite.config.ts        # Vite 构建配置
  +-- tsconfig.json         # TypeScript 编译配置
  +-- tsconfig.node.json    # Node 端 (vite.config) 的 TS 配置
  +-- index.html            # 入口 HTML
  |
  +-- src/
       |
       +-- main.tsx         # React 应用入口
       +-- App.tsx          # 根组件 (布局 + 路由)
       +-- index.css        # 全局样式 (设计系统)
       |
       +-- api/
       |     +-- index.ts   # Axios 封装 + API 模块
       |
       +-- stores/
       |     +-- chatStore.ts  # 聊天状态
       |     +-- uiStore.ts    # UI 状态
       |
       +-- pages/
       |     +-- Chat.tsx         # 对话页
       |     +-- KnowledgeBase.tsx # 知识库页
       |     +-- TaskCenter.tsx   # 任务中心
       |     +-- Settings.tsx     # 配置页
       |
       +-- components/
             +-- TopNav.tsx      # 顶部导航栏
             +-- Sidebar.tsx     # 侧边栏
             +-- DAGPanel.tsx    # DAG 拓扑面板
             +-- ShimmerBar.tsx  # 底部动画条
```

这个结构遵循 React 社区的最佳实践：`pages` 存页面级组件，`components` 存可复用组件，`stores` 存状态管理，`api` 存网络请求封装。

### Vite 是什么？

```
传统工具链:  源码 -> Webpack -> Babel -> 打包 -> 开发服务器
Vite:        源码 -> ESBuild(预打包) -> 原生 ESM -> 开发服务器
```

Vite 的核心优势是"快"：
- 开发服务器启动：Vite 瞬间，Webpack 需要几十秒
- 热更新 (HMR)：Vite 毫秒级，Webpack 秒级
- 原因：Vite 利用浏览器原生 ES Module 能力，无需全量打包

## 项目代码精讲

### 1. package.json — 依赖清单

**文件位置**: `frontend/package.json`

```json
{
  "name": "grasssea-frontend",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "preview": "vite preview",
    "lint": "eslint . --ext ts,tsx"
  },
```

**逐段解析**：

- `"private": true` — 防止误发布到 npm。内部项目标配。
- `"type": "module"` — 启用 ES Module 语法（`import`/`export`），而非旧的 `require`/`module.exports`。
- `"scripts"` — 四个命令：
  - `dev` — 启动开发服务器
  - `build` — 先做类型检查（`tsc -b`），再打包（`vite build`）
  - `preview` — 本地预览打包结果
  - `lint` — 代码规范检查

```json
  "dependencies": {
    "react": "^18.3.1",
    "react-dom": "^18.3.1",
    "react-router-dom": "^6.22.0",
    "antd": "^5.15.0",
    "@ant-design/icons": "^5.3.0",
    "zustand": "^4.5.0",
    "@tanstack/react-query": "^5.24.0",
    "axios": "^1.6.7",
    "react-markdown": "^9.0.1",
    "react-syntax-highlighter": "^15.5.0",
    "remark-gfm": "^4.0.0",
    "dayjs": "^1.11.10"
  },
```

**核心依赖解析**：

| 包名 | 用途 | 为什么选它 |
|------|------|-----------|
| react 18 | UI 框架 | 生态最广，Ant Design 原生支持 |
| antd 5 | UI 组件库 | 企业级，中文支持好，开箱即用 |
| zustand | 状态管理 | 比 Redux 轻量 10 倍，无需 Provider 包裹 |
| tanstack react-query | 服务端缓存 | 自动管理 loading/error/caching |
| axios | HTTP 请求 | 比 fetch 更好的拦截器支持 |
| react-markdown | Markdown 渲染 | AI 输出 Markdown，需要渲染为 HTML |
| react-syntax-highlighter | 代码高亮 | Markdown 中的代码块需要语法高亮 |
| remark-gfm | GFM 扩展 | 支持表格、删除线等扩展 Markdown 语法 |
| dayjs | 日期处理 | 比 moment.js 小 97%，API 兼容 |

```json
  "devDependencies": {
    "@types/react": "^18.3.1",
    "@vitejs/plugin-react": "^4.2.1",
    "typescript": "^5.4.0",
    "vite": "^5.1.0"
  }
```

`devDependencies` 只在开发时需要，不会打包进最终产物。注意所有 `@types/xxx` 包都是 TypeScript 类型定义文件，给 JS 库提供类型提示。

### 2. vite.config.ts — 构建配置

**文件位置**: `frontend/vite.config.ts`

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import path from 'path';

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': path.resolve(__dirname, './src') },
  },
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8001',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
      '/ws': { target: 'ws://localhost:8001', ws: true },
      '/v1': { target: 'http://localhost:8004', changeOrigin: true },
    },
  },
});
```

**逐段解析**：

1. `plugins: [react()]` — 启用 Vite 的 React 插件，处理 JSX 转换和热更新。

2. `alias: { '@': path.resolve(__dirname, './src') }` — **路径别名**。配置后，可以用 `import TopNav from '@/components/TopNav'` 代替 `import TopNav from '../../components/TopNav'`。`@` 是业界约定俗成的前端源码目录别名。

3. `server.proxy` — **开发代理配置**。这是关键配置，因为它解决了"前后端分离开发"的核心问题：

```
浏览器访问 http://localhost:3000 (前端 Vite)

前端请求 /api/chat -->
Vite 代理转发到 http://localhost:8001/chat (后端网关)
                      ^^^^^^^^^    去掉 /api 前缀
```

- `changeOrigin: true` — 修改请求头中的 Host 字段，避免后端 CORS 检查
- `rewrite: (path) => path.replace(/^\/api/, '')` — 去掉 `/api` 前缀后再转发

这意味着前端代码只需写 `/api/chat`，不需要知道后端实际地址。生产环境由 nginx 做同样的反向代理。

### 3. TypeScript 配置策略

GrassSea 使用两个 tsconfig 文件：

```
tsconfig.json       -> 前端源代码的 TS 配置 (src/ 目录)
tsconfig.node.json  -> Node 端代码的配置 (vite.config.ts 等)
```

分离的目的是：前端代码需要 JSX 支持和 DOM 类型，而 vite.config 需要 Node.js 类型，两者不能混用。

**tsconfig.json 核心配置解释**：

```json
{
  "compilerOptions": {
    "target": "ES2020",        // 编译到 ES2020（现代浏览器都支持）
    "jsx": "react-jsx",        // 启用 React 17+ 的新 JSX 转换
    "moduleResolution": "bundler", // 适配 Vite 的模块解析
    "paths": { "@/*": ["./src/*"] }, // 路径别名（对应 vite 的 alias）
    "strict": true             // 启用所有严格类型检查
  }
}
```

- `"jsx": "react-jsx"` — 使用 React 17 引入的新 JSX 转换，不需要在每个文件 `import React`
- `"strict": true` — 一条配置启用所有严格检查（null 检查、类型检查等）

## 常见问题与排错

### Q1: `npm install` 后报大量 peer dependency 警告

**现象**: 终端出现 `UNMET PEER DEPENDENCY` 警告。
**原因**: 某些包的版本不完全匹配依赖声明。
**处理**: peer dependency 警告通常不影响功能。如需消除，用 `npm install --legacy-peer-deps` 安装。

### Q2: 启动 dev 服务器后访问报 404

**原因**: Vite 默认监听 `localhost:3000`，确认地址是否正确。另外检查 `index.html` 是否在项目根目录（Vite 的入口 HTML 必须在根目录）。

### Q3: `@` 别名导入报"找不到模块"

**原因**: TypeScript 不知道 `@` 的含义。
**解决**: 确保 `tsconfig.json` 中配置了 `"paths": { "@/*": ["./src/*"] }`，且 `vite.config.ts` 中配置了 `alias`。两者必须同时配置。

### Q4: 代理不生效，前端请求打到 Vite 自己

**检查步骤**:
1. 确认请求 URL 以 `/api` 开头
2. 确认 `vite.config.ts` 中 `server.proxy` 配置正确
3. 重启 Vite（代理配置修改后需要重启）
