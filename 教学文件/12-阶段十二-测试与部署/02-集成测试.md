## 概念讲解

### 测试金字塔

软件测试分为多个层次，每层有不同目标和成本：

```
          测试金字塔
         ┌─────────┐
         │  E2E    │  端到端测试（很少，最慢，最全面）
         │ (5%)    │  测试整个系统的完整流程
         ├─────────┤  例: 浏览器自动操作 → 前端 → API → 数据库
         │          │
         │ 集成测试 │  集成测试（适中，中等速度）
         │ (15%)   │  测试多个模块的协作
         ├─────────┤  例: FastAPI Route → Service → Database
         │          │
         │          │
         │ 单元测试 │  单元测试（最多，最快，最细致）
         │ (80%)   │  测试单个函数/类
         └─────────┘  例: test_check_permission()

  原则: 越底层的测试越多、越快、越容易维护
        越上层的测试越少、越慢、但越能发现集成问题
```

### 单元测试 vs 集成测试

```
单元测试:
┌────────────────────────────────────────────────┐
│ 测试: 一个函数 check_permission("engineer",  │
│       "tool:use") 是否返回 True？             │
│                                                │
│ 范围: 单个函数                                 │
│ 依赖: 无（不需要数据库、不需要网络）            │
│ 速度: 毫秒级                                   │
│ 问题: 函数写对了，但 API 路由的调用方式写错了  │
│       → 单元测试发现不了这种问题               │
└────────────────────────────────────────────────┘

集成测试:
┌────────────────────────────────────────────────┐
│ 测试: 发送 POST 请求到 /model-gateway/route，  │
│       验证返回的 HTTP 状态码和 JSON 数据       │
│                                                │
│ 范围: HTTP 请求 → 路由 → 服务逻辑 → 响应        │
│ 依赖: 需要启动 FastAPI 应用（可以有测试数据库） │
│ 速度: 秒级                                     │
│ 价值: 验证"端到端的 API 契约"是否正确          │
└────────────────────────────────────────────────┘
```

### httpx 测试 FastAPI 的原理

httpx 是 Python 的现代 HTTP 客户端，支持同步和异步请求。测试 FastAPI 时不需要真正启动一个 HTTP 服务器——使用 `ASGITransport` 可以直接在进程内调用 ASGI 应用。

```
传统方式（需要启动服务器）:
  TestClient ──HTTP──▶ Uvicorn Server ──ASGI──▶ FastAPI App
  慢，需要真实端口，端口可能冲突

ASGI 传输方式（进程内）:
  AsyncClient + ASGITransport ──ASGI──▶ FastAPI App
  快，不需要端口，直接调用 ASGI 接口
```

## 项目代码精讲

GrassSea 的集成测试目录在 `tests/integration/`。虽然当前文件内容较少，但我们可以通过典型的集成测试模式来理解。

### 典型的集成测试结构

```python
import pytest
from httpx import AsyncClient, ASGITransport
from services.model_gateway.main import app

@pytest.fixture
async def client():
    """创建测试客户端（不需要真实端口）"""
    transport = ASGITransport(app=app)
    async with AsyncClient(
        transport=transport, base_url="http://test"
    ) as ac:
        yield ac

@pytest.mark.asyncio
async def test_health_endpoint(client):
    """测试健康检查端点"""
    response = await client.get("/health")
    assert response.status_code == 200
    assert response.json() == {"status": "healthy"}

@pytest.mark.asyncio
async def test_route_endpoint(client):
    """测试模型路由端点"""
    response = await client.post(
        "/v1/route",
        json={
            "model": "deepseek-chat",
            "task_type": "simple_chat",
        },
    )
    assert response.status_code == 200
    data = response.json()
    assert data["model"] == "deepseek-chat"
    assert data["provider"] == "deepseek"

@pytest.mark.asyncio
async def test_invalid_request(client):
    """测试无效请求的错误处理"""
    response = await client.post(
        "/v1/route",
        json={"model": ""},  # 故意传空值
    )
    assert response.status_code == 422
```

**逐段解析**：

1. `ASGITransport(app=app)` — 创建一个 ASGI 传输层，绑定到 FastAPI 应用实例。关键：不需要 `uvicorn.run()`。

2. `AsyncClient(transport=transport, base_url="http://test")` — 创建异步 HTTP 客户端。`base_url` 是必需的，因为 ASGI 模式需要它来确定路由范围。值不重要（`"http://test"`），因为实际不经过网络。

3. `async with AsyncClient(...) as ac:` — 使用异步上下文管理器，确保测试结束后客户端正确关闭。

4. `await client.get("/health")` — 发送 GET 请求到 `/health` 端点。就像真正的 HTTP 请求，但整个过程都在同一进程内。

5. `response.status_code` — 验证 HTTP 状态码。200 表示成功，422 表示请求参数校验失败（FastAPI 的 Pydantic 校验）。

6. `response.json()` — 解析 JSON 响应体。

### 集成测试的常见场景

```
场景一：正常流程（Happy Path）
┌─────────────────────────────────────────────┐
│ POST /rag/query {"query": "散货船规范"}     │
│ 期望: 200, body 包含 answer 和 sources      │
└─────────────────────────────────────────────┘

场景二：参数校验
┌─────────────────────────────────────────────┐
│ POST /rag/query {"query": ""}               │
│ 期望: 422, body 包含验证错误详情            │
└─────────────────────────────────────────────┘

场景三：边界条件
┌─────────────────────────────────────────────┐
│ POST /rag/query {"query": "test",           │
│                   "top_k": 0}               │
│ 期望: 422 (top_k 至少为 1)                  │
└─────────────────────────────────────────────┘

场景四：依赖失败（降级行为）
┌─────────────────────────────────────────────┐
│ 数据库不可用时，/rag/query 应返回 503       │
│ （需要 Mock 或测试数据库）                   │
└─────────────────────────────────────────────┘
```

### 与 CI 流水线的集成

在 GitHub Actions CI（`ci.yml`）中，测试阶段配置了真实的 PostgreSQL 和 Redis：

```yaml
services:
  postgres:
    image: timescale/timescaledb:2.14.2-pg15
    env: { POSTGRES_USER: grasssea, ... }
  redis:
    image: redis:7.2-alpine
```

这意味着 CI 中的集成测试运行在真实的数据库上（而不是 Mock），能够发现数据库查询的 SQL 语法错误、连接超时等问题。

## 手把手实践

### 实验一：编写第一个集成测试

创建 `tests/integration/test_health.py`：

```python
import pytest
from httpx import AsyncClient, ASGITransport
from services.model_gateway.main import app

@pytest.fixture
async def client():
    transport = ASGITransport(app=app)
    async with AsyncClient(
        transport=transport, base_url="http://test"
    ) as ac:
        yield ac

@pytest.mark.asyncio
async def test_health_check(client):
    response = await client.get("/health")
    assert response.status_code == 200
    print("响应内容:", response.json())
```

运行：`pytest tests/integration/test_health.py -v -s`（`-s` 显示 print 输出）。

## 常见问题与排错

**Q1：集成测试运行太慢怎么办？**

A：1) 使用 `ASGITransport`（进程内，最快）；2) 对数据库使用事务回滚（每次测试后回滚，不需要重建数据）；3) 对只读测试共享数据库状态；4) 在 CI 中使用缓存加速数据库启动。

**Q2：集成测试和 E2E 测试的区别？**

A：集成测试在代码层面验证（httpx → ASGI App），E2E 测试在用户层面验证（Selenium → 浏览器 → 真实服务器）。集成测试更快更稳定，E2E 测试更真实但更脆弱。

**Q3：什么时候需要 Mock，什么时候需要真实依赖？**

A：外部 API（如 DeepSeek、Claude）使用 Mock（不可控、要花钱、可能不稳定）；内部服务（如数据库）使用真实实例（需要验证 SQL 正确性、需要验证连接池行为）。
