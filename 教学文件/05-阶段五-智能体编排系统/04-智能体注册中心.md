### 什么是注册中心？

注册中心是微服务架构中的"电话簿"。每个智能体（Agent）启动时向注册中心"报到"，有任务时编排器查询"谁能做这个"。

```
                    智能体注册中心
                   ═══════════════

                   ┌──────────────────┐
                   │   注册中心        │
                   │                  │
                   │  Agents:         │
                   │  ┌─────────────┐ │
                   │  │ pm_agent    │ │ ← IDLE
                   │  │ naval_arch  │ │ ← WORKING
                   │  │ cad_agent   │ │ ← IDLE
                   │  │ review      │ │ ← IDLE
                   │  │ ...         │ │
                   │  └─────────────┘ │
                   │                  │
                   │  能力索引:        │
                   │  "stability" →   │
                   │    naval_arch    │
                   │  "draw" →        │
                   │    cad_agent     │
                   └────────┬─────────┘
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
    ┌──────────┐    ┌──────────┐    ┌──────────┐
    │ PM Agent  │    │Naval Arch│    │CAD Agent │
```

### AgentStatus 枚举

```python
class AgentStatus(str, Enum):
    UNREGISTERED = "unregistered"  # 未注册
    REGISTERED = "registered"      # 已注册
    IDLE = "idle"                  # 空闲（可接收任务）
    WORKING = "working"            # 工作中
    UNHEALTHY = "unhealthy"        # 不健康（心跳超时）
    DESTROYED = "destroyed"        # 已销毁
```

状态流转：

```
UNREGISTERED → REGISTERED → IDLE ←→ WORKING
                                ↓
                           UNHEALTHY → DESTROYED
```

### AgentRegistry 类

```python
class AgentRegistry:
    """智能体注册中心（开发阶段使用内存实现）"""

    def __init__(self):
        self._agents: dict[str, AgentMetadata] = {}     # agent_id → 元信息
        self._status: dict[str, AgentStatus] = {}       # agent_id → 状态
        self._heartbeats: dict[str, float] = {}         # agent_id → 最后心跳时间
        self._heartbeat_timeout = 30                    # 30秒超时
```

三个字典分别存储元信息、状态和心跳时间。开发阶段用内存存储，生产环境应迁移到 Redis 或 Nacos。

### 注册与发现

```python
async def register(self, metadata: AgentMetadata) -> bool:
    self._agents[metadata.agent_id] = metadata
    self._status[metadata.agent_id] = AgentStatus.IDLE
    self._heartbeats[metadata.agent_id] = time.time()
    logger.info("Agent registered", agent_id=metadata.agent_id)
    return True

async def discover(self, capability: str) -> list[AgentMetadata]:
    """按能力发现智能体"""
    results = []
    for agent_id, metadata in self._agents.items():
        for cap in metadata.capabilities:
            if capability in cap.name:            # 子串匹配
                results.append(metadata)
                break
    return results
```

**`capability in cap.name`** 使用的是子串匹配而不是精确匹配。例如搜索 `"stability"` 能匹配到 `"stability_calc"` 能力。但这也意味着搜索 `"draw"` 可能匹配到 `"cad_draw"` 和 `"drawing"`，精确度取决于能力命名的规范性。

### 心跳与健康检查

```python
async def heartbeat(self, agent_id: str) -> bool:
    """Agent 上报心跳"""
    if agent_id in self._agents:
        self._heartbeats[agent_id] = time.time()
        # 如果之前是不健康状态，心跳恢复后标记为 IDLE
        if self._status.get(agent_id) == AgentStatus.UNHEALTHY:
            self._status[agent_id] = AgentStatus.IDLE
        return True
    return False

async def check_health(self) -> None:
    """定时检查所有 Agent 的健康状态"""
    now = time.time()
    for agent_id, last_hb in list(self._heartbeats.items()):
        if now - last_hb > self._heartbeat_timeout:
            if self._status.get(agent_id) != AgentStatus.UNHEALTHY:
                self._status[agent_id] = AgentStatus.UNHEALTHY
                logger.warning("Agent unhealthy", agent_id=agent_id)
```

健康检查应该由定时任务（如 `asyncio.create_task` + `while True: await asyncio.sleep(10)`) 周期性地调用。

### Protocol 接口（解耦设计）

```python
# shared/protocols/agent.py

class AgentRegistry(Protocol):
    """智能体注册中心协议 -- 定义接口契约"""
    async def register(self, agent: BaseAgent) -> bool: ...
    async def deregister(self, agent_id: str) -> bool: ...
    async def discover(self, capability: str) -> list[AgentMetadata]: ...
    async def heartbeat(self, agent_id: str) -> bool: ...
    async def get_agent(self, agent_id: str) -> AgentMetadata | None: ...
```

**Protocol 的作用**：它定义了"注册中心必须有什么方法"，但不规定如何实现。这样：
- 开发阶段：用内存字典
- 生产环境：用 Redis / Nacos / Consul
- 只要实现了相同的协议，切换实现时编排器代码不需要改动

这就是依赖倒置原则（DIP）的体现。

## 手把手实践

### 实验：实现一个迷你注册中心

```python
# mini_registry.py
import time

class MiniRegistry:
    def __init__(self):
        self._agents = {}       # id → {name, capabilities}

    def register(self, agent_id, name, capabilities):
        self._agents[agent_id] = {
            "name": name,
            "capabilities": capabilities,
            "registered_at": time.time(),
        }
        print(f"[注册] {name} 已上线")

    def discover(self, capability):
        results = []
        for aid, info in self._agents.items():
            if capability in info["capabilities"]:
                results.append(info["name"])
        return results

    def list_all(self):
        for aid, info in self._agents.items():
            print(f"  {aid}: {info['name']} → {info['capabilities']}")

# 使用
reg = MiniRegistry()
reg.register("naval_arch", "船舶工程师", ["stability", "hull_design"])
reg.register("cad", "CAD工程师", ["draw", "parse"])

print("谁能做稳性分析？", reg.discover("stability"))
print("谁能画图？", reg.discover("draw"))
reg.list_all()
```

## 常见问题与排错

**Q1：为什么不用 Nacos 而用内存字典？**

A：开发阶段优先简单。内存字典零依赖、秒启动。但生产环境必须使用持久化存储，因为：
- 服务重启后内存数据丢失
- 多实例部署时内存不共享
- 不支持分布式健康检查

**Q2：`discover` 用子串匹配会不会误匹配？**

A：会。这是一个简化实现。改进方案：
- 使用精确匹配（`cap.name == capability`）
- 使用语义匹配（调用 embedding 比较相似度）
- 维护一个能力标签的标准化词汇表

**Q3：Agent 注册失败怎么办？**

A：当前代码中 register 总是返回 True，没有失败场景。生产环境应增加：
- 重名检测（agent_id 冲突）
- 版本兼容性检查
- 依赖工具可用性检查
