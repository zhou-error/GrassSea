## 概念讲解

### 什么是意图识别？

意图识别是对话系统的"前台接待员"——它判断用户想做什么，然后路由到对应的处理逻辑。

```
用户输入："帮我画一张散货船的型线图"
                         │
                         ▼
              ┌─────────────────────┐
              │    意图分类器        │
              │                     │
              │  闲聊？ ❌           │
              │  知识查询？ ❌        │
              │  工具调用？ ✅        │
              │  专业任务？ ✅        │
              │  子代理编排？ ❌      │
              │                     │
              │  → 路由到 Tool/Task │
              └─────────────────────┘
```

### 混合分类策略：两阶段决策

```
用户输入
    │
    ▼
┌─────────────────────────────────────────┐
│        第一阶段：规则引擎（< 50ms）       │
│                                         │
│  关键词/正则匹配                          │
│  覆盖 70% 常见意图                        │
│                                         │
│  例："生成稳性报告"                       │
│    → 匹配规则 (r"生成.*报告", 0.90)       │
│    → confidence=0.90                     │
└──────────────┬──────────────────────────┘
               │
               ▼
       confidence >= 0.85 ?
        │              │
       是              否
        │              │
        ▼              ▼
   ┌────────┐    ┌─────────────────────────┐
   │ 直接路由│    │  第二阶段：LLM 语义层      │
   └────────┘    │  （200-500ms）            │
                 │                          │
                 │  发送给 LLM 进行语义分类    │
                 │  处理复杂/模糊意图          │
                 │                          │
                 │  例："那个东西怎么弄？"      │
                 │    → 规则无法匹配           │
                 │    → LLM 根据上下文判断      │
                 └──────────────┬───────────┘
                                │
                                ▼
                         LLM 也判断不了？
                          │
                          ▼
                    兜底：标记为闲聊
                    或反问用户澄清
```

### 置信度阈值的设计哲学

0.85 的阈值是怎么来的？

```
阈值太低（如 0.5）：
  坏处：规则误判率升高，"你好，帮我算稳性"可能被误判为闲聊
  好处：几乎不需要 LLM，速度快

阈值太高（如 0.95）：
  坏处：大量请求回退到 LLM，延迟高、成本高
  好处：规则判断绝对可靠

0.85 是经验平衡点：
  规则命中的请求，70% 以上 confidence >= 0.85
  剩下的 30% 走 LLM，确保不误判
```

### IntentType 枚举

```python
class IntentType(str, Enum):
    CHITCHAT = "chitchat"                       # 闲聊/寒暄
    KNOWLEDGE_QUERY = "knowledge_query"         # 知识查询
    TOOL_CALL = "tool_call"                     # 工具调用
    PROFESSIONAL_TASK = "professional_task"     # 专业任务
    SUB_AGENT_ORCHESTRATION = "sub_agent_orchestration"  # 多智能体协同
```

使用 `str, Enum` 双重继承，使得枚举值可以像字符串一样使用（例如直接赋值给 JSON 字段）。

**五种意图的含义**：

| 意图 | 典型用户输入 | 后续处理 |
|------|------------|---------|
| CHITCHAT | "你好"、"谢谢你的帮助" | 直接 LLM 回复 |
| KNOWLEDGE_QUERY | "CCS规范对舱壁间距有什么要求？" | 调用 RAG 引擎 |
| TOOL_CALL | "帮我生成一份稳性报告" | 规划单步工具调用 |
| PROFESSIONAL_TASK | "对这艘船的稳性进行分析计算" | 规划多步专业任务 |
| SUB_AGENT_ORCHESTRATION | "从设计到审查完整做一遍" | 多智能体协同编排 |

### 规则引擎：RULE_PATTERNS

这是一个典型的"规则即数据"设计：

```python
RULE_PATTERNS: dict[IntentType, list[tuple[str, float, list[str]]]] = {
    IntentType.CHITCHAT: [
        (r"^(你好|嗨|hello|hi|早上好|晚上好|下午好)[\s!！。.,，]*$", 0.95, ["greeting"]),
        (r"(谢谢|感谢|多谢|thank)", 0.95, ["thanks"]),
        (r"(再见|拜拜|bye|回头见)", 0.95, ["farewell"]),
        (r"(你是谁|你叫什么|介绍.*自己|你能做什么|功能|帮助|help)", 0.90, ["self_intro"]),
    ],
    IntentType.KNOWLEDGE_QUERY: [
        (r"(规范|标准|要求|规定|条文|CCS|IMO|SOLAS|MARPOL)", 0.90, ["regulation"]),
        # ...更多规则
    ],
    # ...更多意图类型
}
```

每个规则是一个三元组：`(正则表达式, 置信度, 匹配标签列表)`

**规则的书写技巧**：
- CHITCHAT 规则使用了 `^...$` 锚定，确保只匹配纯问候语
- KNOWLEDGE_QUERY 使用了多个行业关键词（CCS、IMO、SOLAS...）
- PROFESSIONAL_TASK 使用了高度专业化的术语（稳性、静水力、邦戎曲线...）

### 核心分类逻辑

```python
async def classify(self, text: str) -> IntentResult:
    # 1. 规则引擎匹配
    rule_result = self._rule_match(text)

    # 2. 置信度判断
    if rule_result and rule_result.confidence >= self.confidence_threshold:
        return rule_result  # <—— 快速路径，不调用 LLM

    # 3. 递升到 LLM 分类
    llm_result = await self._llm_classify(text)
    if llm_result:
        return llm_result

    # 4. 兜底：默认为闲聊
    if rule_result:
        return rule_result
    return IntentResult(intent_type=IntentType.CHITCHAT, confidence=0.5)
```

这是一个典型的**分层决策**模式：快速层（规则）-> 精确层（LLM）-> 兜底层。

```python
def _rule_match(self, text: str) -> IntentResult | None:
    """规则引擎匹配 -- 遍历所有规则，找最高置信度的匹配"""
    best_intent = None
    best_confidence = 0.0
    best_rules = []

    for intent_type, patterns in RULE_PATTERNS.items():
        for pattern, confidence, rules in patterns:
            if re.search(pattern, text, re.IGNORECASE):
                if confidence > best_confidence:
                    best_confidence = confidence
                    best_intent = intent_type
                    best_rules = rules

    if best_intent:
        entities = self._extract_entities(text)
        return IntentResult(
            intent_type=best_intent,
            confidence=best_confidence,
            matched_rules=best_rules,
            extracted_entities=entities,
        )
    return None
```

**"不是第一个匹配就返回"**：代码遍历了所有规则，取置信度最高的匹配。这样如果用户说"你好，帮我查一下CCS规范"（同时匹配 CHITCHAT 和 KNOWLEDGE_QUERY），会命中 KNOWLEDGE_QUERY（confidence 0.90 > 0.85），符合用户的真实意图。

### 实体提取

```python
def _extract_entities(self, text: str) -> dict:
    """从用户输入中提取结构化信息"""
    entities = {}

    # 船型识别
    ship_types = ["散货船", "油船", "集装箱船", "客船", ...]
    for st in ship_types:
        if st in text:
            entities["ship_type"] = st
            break

    # 规范识别
    regulations = ["CCS", "DNV", "ABS", "LR", "BV", "IMO", "SOLAS", ...]
    for reg in regulations:
        if reg.lower() in text.lower():
            entities.setdefault("regulations", []).append(reg)

    # 参数识别
    param_match = re.findall(
        r"(船长|型宽|型深|吃水|排水量|方型系数|棱形系数|航速|载重量)", text
    )
    if param_match:
        entities["parameters"] = param_match

    return entities
```

实体提取的结果用于后续的任务规划和参数填充。例如提取到 `ship_type: "散货船"` 和 `regulations: ["CCS"]`，任务规划器就能直接限定检索范围。

# my_intent.py -- 10分钟理解意图分类
import re

def classify_intent(text: str):
    """最简单的意图分类：只区分三种意图"""
    rules = {
        "greeting": [(r"^(你好|hi|hello)", 0.95)],
        "search": [(r"(搜索|查|找|检索)", 0.85)],
        "calculate": [(r"(计算|算|求解)", 0.85)],
    }

    best_intent = "unknown"
    best_conf = 0

    for intent, patterns in rules.items():
        for pattern, conf in patterns:
            if re.search(pattern, text, re.IGNORECASE):
                if conf > best_conf:
                    best_conf = conf
                    best_intent = intent

    return best_intent, best_conf

## 常见问题与排错

**Q1：为什么不用全 LLM 分类，而要用规则引擎？**

A：三个原因：
1. **延迟**：LLM 分类 200-500ms，规则引擎 < 1ms
2. **成本**：每次 LLM 调用都有 Token 费用
3. **可靠性**：规则 100% 确定，"查规范"永远是 KNOWLEDGE_QUERY；LLM 偶有波动

**Q2：规则太多维护不过来怎么办？**

A：当前规则只有约 30 条，可控。如果扩展到数百条，可以考虑：
1. 将规则抽取到 YAML/JSON 配置文件
2. 使用 Aho-Corasick 多模匹配算法加速
3. 引入规则优先级和冲突解决机制

**Q3：LLM 分类返回的不是合法 JSON 怎么办？**

A：当前代码使用 `json.loads()` 直接解析，如果 LLM 返回多余内容会报错。改进方案：
- 使用 `re.search(r"\{[\s\S]*\}", content)` 提取 JSON 部分（planner.py 中就有这个技巧）
- 捕获异常后降级为规则结果
