## 概念讲解

### 一、为什么需要模型路由

不同任务需要不同能力的模型：

| 任务类型 | 需求 | 最优模型 | 原因 |
|---------|------|---------|------|
| 简单对话 | 快速、低成本 | deepseek-chat | 性价比最高 |
| 知识库问答 | 准确、中文好 | deepseek-chat | 中文能力强 |
| 复杂推理 | 深度思考 | deepseek-reasoner | 链式推理 |
| 代码生成 | 代码理解 | deepseek-coder | 专门训练的代码模型 |
| 意图分类 | 快速、分类准 | qwen2.5-7b | 小模型推理快 |
| 报告生成 | 长文、结构化 | claude-opus-4-8 | 长文写作顶级 |

如果没有路由策略，开发者需要：
1. 记住每个任务的推荐模型
2. 手动在代码中切换模型名
3. 主模型不可用时手动换备选

模型路由自动化了这个过程。

### 二、路由策略的两种模式

**模式 1：用户指定优先**（GrassSea 采用）

```
用户请求指定了 model → 优先使用用户指定的模型
用户没有指定 model → 按任务类型自动选择
主模型不可用 → 自动降级到备选模型
```

```
请求: model="deepseek-chat"
  │
  ├── deepseek-chat 可用？ ──Yes──> 使用 deepseek-chat
  │
  └── No ──> 返回错误 "模型不可用"

请求: model="" (未指定)
  │
  ├── task_type="complex_reasoning"
  ├── 主模型: deepseek-reasoner
  ├── deepseek-reasoner 可用？ ──Yes──> 使用 deepseek-reasoner
  │
  └── No ──> 使用备选模型 claude-opus-4-8
```

**模式 2：强制按任务路由**（忽略用户指定）

```
不论用户指定什么 model，都按任务类型重新分配。
适合完全托管的平台（如企业内部平台）。
```

GrassSea 选择模式 1 因为它给予用户控制权，同时提供智能默认值。

## 项目代码精讲

### 数据模型

```python
@dataclass
class ModelRouteRequest:
    """模型路由请求"""
    model: str = "deepseek-chat"
    messages: list[dict] = field(default_factory=list)
    task_type: str = "simple_chat"
    temperature: float = 0.7
    max_tokens: int = 4096

@dataclass
class ModelRouteResult:
    """模型路由结果"""
    model: str
    provider: str
    api_key: str
    base_url: str
    task_type: str
    prompt_tokens: int | None = None
    completion_tokens: int | None = None
```

使用 `@dataclass` 而不是 `BaseModel` 的原因是：这些是内部数据类，不需要 JSON 序列化验证。`dataclass` 更轻量、更快。

### 任务-模型映射表

```python
TASK_MODEL_MAP = {
    "simple_chat":            ("deepseek-chat",      "claude-haiku"),
    "knowledge_qa":           ("deepseek-chat",      "claude-sonnet"),
    "complex_reasoning":      ("deepseek-reasoner",  "claude-opus-4-8"),
    "code_generation":        ("deepseek-coder",     "claude-sonnet"),
    "intent_classification":  ("qwen2.5-7b",        "deepseek-chat"),
    "report_generation":      ("claude-opus-4-8",    "deepseek-reasoner"),
}
#                              (主模型,              备选模型)
```

每个任务类型绑定一对模型：主模型 + 备选模型。这是一种**策略模式**——定义不同的路由策略，运行时根据任务类型选择。

**设计决策解读**：

```
simple_chat → deepseek-chat (主)
理由: DeepSeek 中文对话流畅，且成本远低于 Claude

complex_reasoning → deepseek-reasoner (主)
理由: DeepSeek-R1 的链式推理能力极强

report_generation → claude-opus-4-8 (主)
理由: Claude 在长文写作和结构化输出方面更优

intent_classification → qwen2.5-7b (主)
理由: 意图分类不需要大模型，7B 足够且速度快 10 倍
```

### 模型初始化

```python
class ModelRouter:
    def __init__(self, settings: Settings):
        self.settings = settings
        self._http_client: httpx.AsyncClient | None = None
        self.model_map: dict[str, dict[str, str]] = {}

    async def initialize(self) -> None:
        self._http_client = httpx.AsyncClient(
            timeout=httpx.Timeout(120.0, connect=10.0),
            limits=httpx.Limits(max_connections=50, max_keepalive_connections=10),
        )

        # 根据 API Key 是否配置来注册模型
        if self.settings.DEEPSEEK_API_KEY:
            self.model_map["deepseek-chat"] = {
                "provider": "deepseek",
                "api_key": self.settings.DEEPSEEK_API_KEY,
                "base_url": self.settings.DEEPSEEK_BASE_URL.rstrip("/"),
            }
            self.model_map["deepseek-reasoner"] = {
                "provider": "deepseek",
                "api_key": self.settings.DEEPSEEK_API_KEY,
                "base_url": self.settings.DEEPSEEK_BASE_URL.rstrip("/"),
            }
            self.model_map["deepseek-coder"] = {
                "provider": "deepseek",
                "api_key": self.settings.DEEPSEEK_API_KEY,
                "base_url": self.settings.DEEPSEEK_BASE_URL.rstrip("/"),
            }

        if self.settings.CLAUDE_API_KEY:
            self.model_map["claude-haiku"] = {
                "provider": "anthropic",
                "api_key": self.settings.CLAUDE_API_KEY,
                "base_url": self.settings.CLAUDE_BASE_URL.rstrip("/"),
            }
            # ... sonnet, opus 同理
```

**模型注册是条件性的**——只有当 API Key 存在时才注册。这保证了"配置了什么就能用什么"，不会出现配置缺失导致的运行时错误。

### 核心路由逻辑

```python
async def route(self, request: ModelRouteRequest) -> ModelRouteResult:
    model_name = request.model

    # 第 1 步：用户指定模型且可用 → 直接使用
    if model_name in self.model_map:
        model_config = self.model_map[model_name]
        return ModelRouteResult(
            model=model_name,
            provider=model_config["provider"],
            api_key=model_config["api_key"],
            base_url=model_config["base_url"],
            task_type=request.task_type,
        )

    # 第 2 步：按任务类型路由
    primary, fallback = TASK_MODEL_MAP.get(
        request.task_type, ("deepseek-chat", "claude-haiku")
    )

    # 第 3 步：尝试主模型
    if primary in self.model_map:
        model_config = self.model_map[primary]
        return ModelRouteResult(
            model=primary,
            provider=model_config["provider"],
            api_key=model_config["api_key"],
            base_url=model_config["base_url"],
            task_type=request.task_type,
        )

    # 第 4 步：主模型不可用，降级到备选
    if fallback in self.model_map:
        model_config = self.model_map[fallback]
        logger.warning("Model fallback", primary=primary, fallback=fallback)
        return ModelRouteResult(
            model=fallback,
            provider=model_config["provider"],
            api_key=model_config["api_key"],
            base_url=model_config["base_url"],
            task_type=request.task_type,
        )

    # 第 5 步：都不可用，报错
    raise ValueError(f"No available model for task '{request.task_type}'")
```

路由决策树：

```
route(request)
│
├─ 用户指定了 model？
│   ├─ Yes → model 在 model_map 中？
│   │         ├─ Yes → 使用（返回）
│   │         └─ No → 继续（按任务类型路由）
│   │
│   └─ No → 按任务类型路由
│
├─ task_type 在 TASK_MODEL_MAP 中？
│   ├─ Yes → (primary, fallback)
│   └─ No → ("deepseek-chat", "claude-haiku")  ← 默认
│
├─ primary 在 model_map 中？
│   ├─ Yes → 使用 primary（返回）
│   └─ No → 尝试 fallback
│
├─ fallback 在 model_map 中？
│   ├─ Yes → 使用 fallback（记录 warning）
│   └─ No → 抛出 ValueError
```

### 多 Provider 适配

```python
async def complete(self, route: ModelRouteResult, stream: bool = False) -> dict:
    if route.provider == "deepseek":
        return await self._call_deepseek(route, stream=False)
    elif route.provider == "anthropic":
        return await self._call_claude(route, stream=False)
    else:
        raise ValueError(f"Unknown provider: {route.provider}")
```

**策略模式的应用**：路由结果中包含了 `provider` 字段，调用时根据 provider 分发到不同的处理方法。

### DeepSeek 调用（OpenAI 兼容格式）

```python
async def _call_deepseek(self, route: ModelRouteResult, stream: bool = False) -> dict:
    url = f"{route.base_url}/v1/chat/completions"
    headers = {
        "Authorization": f"Bearer {route.api_key}",
        "Content-Type": "application/json",
    }
    payload = {
        "model": route.model,
        "messages": [{"role": "user", "content": "ping"}],
        "stream": stream,
    }

    response = await self._http_client.post(url, json=payload, headers=headers)
    response.raise_for_status()
    data = response.json()
    choice = data["choices"][0]

    return {
        "content": choice["message"]["content"],
        "prompt_tokens": data.get("usage", {}).get("prompt_tokens", 0),
        "completion_tokens": data.get("usage", {}).get("completion_tokens", 0),
    }
```

**适配逻辑**：

```
LLM Provider → 网关内部格式 → 统一响应

DeepSeek (OpenAI 格式)  ──> 直接解析 choices[0].message.content
Claude (Anthropic 格式) ──> 适配 content[0].text
GPT (OpenAI 格式)       ──> 同 DeepSeek
```

### Claude 调用（Anthropic 格式）

```python
async def _call_claude(self, route: ModelRouteResult, stream: bool = False) -> dict:
    url = f"{route.base_url}/v1/messages"                    # 不同的 URL
    headers = {
        "x-api-key": route.api_key,                          # 不同的认证头
        "anthropic-version": "2023-06-01",                    # Anthropic 特有的版本头
        "Content-Type": "application/json",
    }
    payload = {
        "model": route.model,
        "max_tokens": 4096,
        "messages": [{"role": "user", "content": "ping"}],
    }

    response = await self._http_client.post(url, json=payload, headers=headers)
    response.raise_for_status()
    data = response.json()

    # 不同的响应结构
    content_blocks = data.get("content", [{}])
    text = "".join(
        block.get("text", "") for block in content_blocks if block.get("type") == "text"
    )

    return {
        "content": text,
        "prompt_tokens": data.get("usage", {}).get("input_tokens", 0),    # 不同的字段名
        "completion_tokens": data.get("usage", {}).get("output_tokens", 0),
    }
```

**DeepSeek vs Claude API 差异对比**：

| 维度 | DeepSeek (OpenAI 兼容) | Claude (Anthropic) |
|------|----------------------|-------------------|
| URL | `/v1/chat/completions` | `/v1/messages` |
| 认证 | `Authorization: Bearer xxx` | `x-api-key: xxx` |
| 响应内容 | `choices[0].message.content` | `content[0].text` |
| Prompt Token | `usage.prompt_tokens` | `usage.input_tokens` |
| Completion Token | `usage.completion_tokens` | `usage.output_tokens` |

网关将这些差异封装起来，对外提供统一的接口。

## 常见问题与排错

### Q1: 为什么 `_call_deepseek` 中的 messages 是 `"ping"`？
这是示例模板。实际使用时，`route_request.messages` 会覆盖这个占位值。代码中保留 `"ping"` 只是为框架保持结构完整性。

### Q2: fallback 模型也失败了怎么办？
当前代码会抛出 `ValueError`，导致返回 400 错误。生产环境中应该加入更完善的错误处理（如重试、队列降级、使用缓存响应）。

### Q3: 如何添加负载均衡（多个相同模型实例）？
可以在 `model_map` 中存储多个 endpoint，路由时轮询选择：

```python
self.model_map["deepseek-chat"] = [
    {"provider": "deepseek", "api_key": key1, "base_url": url1},
    {"provider": "deepseek", "api_key": key2, "base_url": url2},
]
```

### Q4: 路由策略如何动态更新？
`/admin/reload` 端点实现了热加载——修改环境变量后，重新初始化 `ModelRouter`，新的 API Key 和模型配置立即生效。
