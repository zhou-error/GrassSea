## 概念讲解

### 为什么需要工具协议？

在 GrassSea 多智能体平台中，有数十种工具：静水力计算、稳性分析、PDF解析、CAD绘图等。这些工具来自不同模块、由不同开发者编写。如果没有统一的协议，智能体编排服务就无法知道"这个工具有什么参数？它返回什么数据？它是否在线？"。

工具协议要解决的问题：

```
                          +-------------------+
                          |  Agent 编排服务    |
                          |  (调用方)          |
                          +--------+----------+
                                   |
                    统一协议（BaseTool / ToolManifest）
                                   |
          +------------+-----------+------------+-----------+
          |            |           |            |           |
    静水力计算    稳性分析     PDF解析     CAD绘图     报告生成
```

### 核心架构（ASCII 图解）

```
+------------------------------------------------------+
|              工具注册中心 (ToolRegistry)                |
|  _tools: dict[str, BaseTool]                          |
|                                                       |
|  提供: register / deregister / get_tool / list_tools  |
|        execute_tool / health_check_all                |
+------------------------------------------------------+
           |                          |
    注册时调用                 运行时调用
           |                          |
    +------v-------+          +------v------+
    |  _validate   |          |  execute    |
    |  (校验兼容性) |          |  (执行工具)  |
    +--------------+          +-------------+

工具生命周期:
  DEVELOPING -> REGISTERED -> ONLINE -> DEGRADED/OFFLINE
```

### ToolCategory 枚举 — 工具分类

```python
class ToolCategory(str, Enum):
    COMPLIANCE   = "compliance"   # 合规审查
    CAD          = "cad"          # CAD 操作
    COMPUTATION  = "computation"  # 数值计算
    REPORT       = "report"       # 报告生成
    FILE         = "file"         # 文件处理
    SEARCH       = "search"       # 检索
    EXTERNAL     = "external"     # 外部集成
```

一共有7个分类。每个工具必须属于其中一个分类，注册中心会用它来筛选和分组工具。

### ToolStatus 枚举 — 工具状态

```
DEVELOPING  ->  REGISTERED  ->  ONLINE
                                     |
                                     v
                                DEGRADED  ->  ONLINE (恢复)
                                     |
                                     v
                                OFFLINE
```

- **DEVELOPING**: 正在开发，还没注册
- **REGISTERED**: 已通过校验，存入注册中心
- **ONLINE**: 健康检查通过，可以接收请求
- **DEGRADED**: 健康检查失败，自动降级
- **OFFLINE**: 主动下线
- **REJECTED**: 校验失败，拒绝注册

### ToolManifest 数据类 — 工具的"身份证"

```python
@dataclass
class ToolManifest:
    tool_id: str           # 唯一标识，如 "hydrostatics"
    name: str              # 中文名称，如 "静水力计算"
    description: str       # 功能描述
    category: ToolCategory # 所属分类
    input_schema: dict     # 输入参数的 JSON Schema
    output_schema: dict    # 输出结果的 JSON Schema
    timeout_ms: int = 30000       # 超时时间（毫秒）
    requires_auth: bool = True    # 是否需要鉴权
    rate_limit_per_min: int = 60  # 每分钟限频
    version: str = "0.1.0"        # 语义化版本号
```

`input_schema` 和 `output_schema` 遵循 JSON Schema 标准，这让前端可以自动生成表单，也让智能体可以理解工具的输入输出格式。

## 项目代码精讲

### 1. BaseTool — 工具抽象基类

**文件位置**: `shared/protocols/tool.py`

```python
class BaseTool(ABC):
    """工具抽象基类 — 所有工具需继承此类，实现 execute 方法。"""

    def __init__(self, manifest: ToolManifest):
        self._manifest = manifest
        self._status = ToolStatus.DEVELOPING
```

**逐段解析**:

1. `class BaseTool(ABC):` — 继承 `ABC`（Abstract Base Class），使其成为抽象基类。这意味着不能直接 `BaseTool()` 创建实例，必须先继承并实现抽象方法。

2. `def __init__(self, manifest: ToolManifest):` — 构造函数接收一个 `ToolManifest` 对象。每个工具在创建时必须提供自己的"身份证"。

3. `self._manifest = manifest` — 保存工具的元信息。前面加下划线 `_manifest` 表示这是"私有"属性，外部应该通过 `manifest` 属性访问。

4. `self._status = ToolStatus.DEVELOPING` — 初始状态是"开发中"。

接下来是核心方法：

```python
@property
def manifest(self) -> ToolManifest:
    """返回工具元信息"""
    return self._manifest
```

`@property` 装饰器让 `manifest` 可以像属性一样访问（`tool.manifest`），而不是方法调用（`tool.manifest()`）。这是一种 Python 惯用法，让只读数据的访问更自然。

```python
@abstractmethod
async def execute(
    self,
    params: dict[str, Any],
    context: dict[str, Any],
) -> dict[str, Any]:
    """执行工具并返回结果"""
    ...
```

`@abstractmethod` 表示这是抽象方法，子类**必须**实现它。方法签名中的 `...` 是合法的 Python 占位符，表示"这里没有实现，让子类来填"。

- `params` — 工具参数，由调用方传入（如 `{"L": 100, "B": 15}`）
- `context` — 用户会话上下文（如用户ID、会话ID等）
- 返回值 — 统一返回 `dict`，包含 `"status"` 字段

```python
async def validate_params(self, params: dict[str, Any]) -> bool:
    """参数校验（默认通过，子类可覆盖）"""
    return True

async def health_check(self) -> bool:
    """健康检查"""
    return True
```

这两个方法有默认实现（都返回 `True`），子类可以按需覆盖。这种设计叫"模板方法模式"——基类提供默认行为，子类只需关注自己的特殊逻辑。

### 2. ToolRegistry — 工具注册中心

**文件位置**: `tools/base/registry.py`

```python
class ToolRegistry:
    """工具注册中心（支持热插拔）"""

    def __init__(self):
        self._tools: dict[str, BaseTool] = {}
        self._health_interval = 30  # 健康检查间隔（秒）
```

`_tools` 是一个字典，key 是 `tool_id`，value 是 `BaseTool` 实例。这是注册中心的核心数据结构。

**热插拔注册流程**：

```python
async def register(self, tool: BaseTool) -> bool:
    """注册工具（自动校验接口兼容性）"""
    manifest = tool.manifest
    if manifest.tool_id in self._tools:
        logger.warning("Tool already registered, replacing", tool_id=manifest.tool_id)
        await self.deregister(manifest.tool_id)

    if not await self._validate_tool(tool):
        tool.set_status(ToolStatus.REJECTED)
        logger.error("Tool validation failed", tool_id=manifest.tool_id)
        return False

    self._tools[manifest.tool_id] = tool
    tool.set_status(ToolStatus.REGISTERED)

    if await tool.health_check():
        tool.set_status(ToolStatus.ONLINE)

    logger.info("Tool registered", tool_id=manifest.tool_id, status=tool.status.value)
    return True
```

**逐段解析**：

1. 如果 `tool_id` 已存在，先注销旧工具（热替换）
2. 调用 `_validate_tool` 进行兼容性校验
3. 校验失败则标记为 `REJECTED` 并返回 `False`
4. 校验通过后放入 `_tools` 字典，标记为 `REGISTERED`
5. 运行健康检查，如果通过则升级为 `ONLINE`

这就是"热插拔"的完整流程——不需要重启服务，运行时调用 `register()` 就能动态添加/替换工具。

**执行工具的核心方法**：

```python
async def execute_tool(self, tool_id: str, params: dict, context: dict) -> dict:
    tool = await self.get_tool(tool_id)
    if not tool:
        return {"status": "error", "message": f"Tool '{tool_id}' not found"}
    if tool.status != ToolStatus.ONLINE:
        return {"status": "error", "message": f"Tool '{tool_id}' is {tool.status.value}"}

    try:
        if not await tool.validate_params(params):
            return {"status": "error", "message": "Parameter validation failed"}
        result = await asyncio.wait_for(
            tool.execute(params, context),
            timeout=tool.manifest.timeout_ms / 1000,
        )
        return result
    except asyncio.TimeoutError:
        return {"status": "error", "message": "Tool execution timeout"}
```

关键设计点：
- **状态检查**: 只有 `ONLINE` 的工具才能被执行
- **参数校验**: 执行前先验证参数合法性
- **超时保护**: 使用 `asyncio.wait_for` 限制执行时间，防止某个工具卡死影响整个系统
- **错误兜底**: 捕获所有异常，返回统一的错误格式，避免"一个工具崩溃导致整个服务崩溃"

**自动降级与恢复**：

```python
async def health_check_all(self) -> dict[str, bool]:
    for tool_id, tool in list(self._tools.items()):
        try:
            healthy = await tool.health_check()
            if healthy and tool.status == ToolStatus.DEGRADED:
                tool.set_status(ToolStatus.ONLINE)   # 自动恢复
            elif not healthy and tool.status == ToolStatus.ONLINE:
                tool.set_status(ToolStatus.DEGRADED)  # 自动降级
        except Exception:
            tool.set_status(ToolStatus.DEGRADED)      # 异常降级
```

这段代码展示了注册中心的"自愈"能力——定期检查所有工具的健康状态，自动将故障工具降级，恢复后自动上线。

## 手把手实践

### 实践目标：编写一个"船舶安全系数计算"工具并注册

**第1步：创建工具文件** `my_tools/safety_factor.py`

```python
from shared.protocols.tool import BaseTool, ToolCategory, ToolManifest

SAFETY_MANIFEST = ToolManifest(
    tool_id="safety_factor",
    name="安全系数计算",
    description="根据载重和工况计算结构安全系数",
    category=ToolCategory.COMPUTATION,
    input_schema={
        "type": "object",
        "properties": {
            "deadweight": {"type": "number"},
            "sea_state": {"type": "integer"}
        }
    },
    output_schema={
        "type": "object",
        "properties": {
            "factor": {"type": "number"},
            "level": {"type": "string"}
        }
    },
    timeout_ms=10000,
    version="0.1.0",
)

class SafetyFactorTool(BaseTool):
    def __init__(self):
        super().__init__(SAFETY_MANIFEST)

    async def execute(self, params: dict, context: dict) -> dict:
        dwt = params.get("deadweight", 10000)
        sea = params.get("sea_state", 3)
        # 简单计算：载重越大，海况越高，安全系数要求越高
        factor = dwt / 1000 * (1 + sea * 0.2)
        level = "安全" if factor < 30 else "需加强"
        return {
            "status": "completed",
            "factor": round(factor, 2),
            "level": level,
        }

    async def validate_params(self, params: dict) -> bool:
        # 覆盖默认校验：确保参数为正数
        return all(
            v > 0 for v in [params.get("deadweight", 1), params.get("sea_state", 1)]
        )
```

**第2步：注册并调用工具**

```python
import asyncio
from tools.base.registry import ToolRegistry
from my_tools.safety_factor import SafetyFactorTool

async def main():
    registry = ToolRegistry()

    # 注册
    tool = SafetyFactorTool()
    success = await registry.register(tool)
    print(f"注册结果: {success}, 状态: {tool.status}")

    # 执行
    result = await registry.execute_tool(
        "safety_factor",
        {"deadweight": 15000, "sea_state": 5},
        {"user_id": "test_user"},
    )
    print(f"执行结果: {result}")

asyncio.run(main())
```

**预期输出**:
```
注册结果: True, 状态: online
执行结果: {'status': 'completed', 'factor': 30.0, 'level': '需加强'}
```

### 实践关键点

1. **Manifest 必须完整**: `tool_id` 和 `name` 不能为空，`input_schema` 和 `output_schema` 不能为空
2. **execute 必须返回 dict**: 且建议包含 `"status"` 字段
3. **不要忘记 `await`**: 所有方法都是异步的，调用时必须用 `await`
4. **注册机的 `_tools` 字典**使用 `tool_id` 作为 key，所以 `tool_id` 必须唯一

## 常见问题与排错

### Q1: 注册时校验失败，返回 REJECTED

**排查步骤**:
1. 检查 `tool_id` 和 `name` 是否为空字符串
2. 检查 `input_schema` 和 `output_schema` 是否是空的 `dict`
3. 检查 `timeout_ms` 是否 > 0

### Q2: execute_tool 返回 "Tool execution timeout"

**原因**: 工具执行时间超过了 `manifest.timeout_ms` 设定值。
**解决**:
- 检查工具中的耗时操作（如 HTTP 请求、大文件读取）
- 适当增大 `timeout_ms`（如 `60000` 表示 60 秒）
- 将耗时操作拆分为异步任务

### Q3: tool_id 重复导致旧工具被替换

**现象**: 日志中出现 "Tool already registered, replacing"
**说明**: 这是正常行为，注册中心会先注销旧工具再注册新的。利用这个机制可以实现工具的"热更新"。

### Q4: 为什么 execute 方法必须是 async 的？

因为工具可能执行耗时操作（如调用外部 API、读取大文件、数据库查询），如果使用同步方法，会阻塞整个事件循环。`async/await` 让 Python 在等待 I/O 时可以去处理其他请求。
