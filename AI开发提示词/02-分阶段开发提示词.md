# 白草沧智（GrassSea AI）项目分阶段开发提示词

> **文档用途**：依据《白草沧智（GrassSea AI）项目框架设计文档》（v1.0，2026-07-02）指导 AI 分阶段进行项目开发。  
> **适用对象**：AI 编程助手（如 DeepSeek、Claude 等）或项目技术负责人。  
> **版本**：v1.0  
> **编写日期**：2026-07-04

---

## 总体要求

我准备基于《白草沧智（GrassSea AI）项目框架设计文档》（版本 v1.0，2026-07-02）进行实际开发。项目目标是以该文档为蓝图，实现一个面向船舶与海洋工程领域的 AI 原生多智能体协作平台。请你作为项目技术负责人，**严格按照文档中的分层架构、技术选型、接口规范、业务流程和运维设计，制定一套分阶段开发计划，并依次执行每个阶段的开发任务**。

### 开发原则

1. **严格遵从文档**：所有设计决策（架构、技术栈、协议、数据库、接口等）以文档为准，不自行修改或引入新方案。
2. **可运行、可验证**：每个阶段结束时必须产出可运行（至少可本地启动）的模块，并提供明确的验收标准。
3. **文档驱动**：所有代码、配置文件和文档的变更需同步更新项目文档（如 README、API 规范、部署说明）。
4. **测试先行**：关键逻辑（工具调用、Agent 接口、RAG 检索等）需伴随单元测试或集成测试。
5. **渐进式开发**：优先实现核心链路（对话 + 知识检索 + 简单任务），再逐步扩展智能体和工具。

### 阶段划分与任务清单

请按以下阶段顺序执行，**每个阶段完成后，向我报告进度并等待确认后再进入下一阶段**。

## 阶段 0：基础设施与环境搭建

**目标**：搭建本地开发环境，完成容器编排基础配置，确保所有中间件可一键启动。

**任务清单**：

- [ ] 创建项目代码仓库（目录结构按文档 **附录 B** 创建）。
- [ ] 编写 `docker-compose.yml`，包含以下服务：
  - PostgreSQL 15（含 TimescaleDB 扩展）
  - MongoDB 7
  - Redis 7
  - Milvus 2.4+
  - MinIO（latest）
  - RabbitMQ 3.12+
  - （可选）Nacos 2.x 或暂用 Consul 替代
- [ ] 编写各服务的 Dockerfile（Python 3.11+，基于 FastAPI）。
- [ ] 配置 K3s 本地集群（或使用 `kind`/`minikube` 模拟），准备 `k3s/` 目录下的资源清单（Namespace、Deployment、Service、ConfigMap）。
- [ ] 实现统一配置管理（使用 `.env` + `settings.py`，支持环境变量覆盖）。
- [ ] 实现基础日志模块（结构化日志，JSON 格式，输出到控制台）。
- [ ] 编写 `Makefile`，包含常用命令（`make up`、`make down`、`make test`、`make lint` 等）。

**验收标准**：

- 执行 `docker-compose up -d` 后，所有中间件健康检查通过。
- 能通过 `psql`、`mongosh`、`redis-cli` 等客户端连接到对应服务。
- MinIO 可正常访问，并能创建 bucket（如 `grasssea-files`）。
- 基础 Python 项目结构完整，`pytest` 可运行（至少一个占位测试通过）。

## 阶段 1：核心数据模型与数据库设计

**目标**：设计并实现数据库表/集合/索引，建立 ORM 模型，完成数据底座的初始化。

**任务清单**：

- [ ] 根据文档 **2.5 数据底座层** 和 **附录 A**，设计以下数据库 schema：
  - PostgreSQL：用户表、权限表（RBAC）、项目表、任务记录表、型值表、待办事项表。
  - MongoDB：对话历史、审查报告（JSON）、Agent 配置、任务 DAG、调研报告。
  - TimescaleDB：Token 统计、API 延迟、工具调用频次等时序表（使用 hypertable）。
  - Neo4j（可延后）：船舶本体知识图谱（先设计节点和关系 schema）。
- [ ] 使用 SQLAlchemy（异步）定义 PostgreSQL 模型，并使用 Alembic 管理迁移。
- [ ] 使用 Motor（异步）定义 MongoDB 集合结构及索引。
- [ ] 实现数据访问层（Repository 模式），提供 CRUD 接口供上层调用。
- [ ] 初始化 MinIO bucket 结构（规范库、项目知识库、图纸、报告等目录）。
- [ ] 编写基础数据初始化脚本（如创建默认管理员角色、系统配置项）。

**验收标准**：

- 所有表/集合创建完毕，可通过 ORM 进行基本的增删改查。
- Alembic 迁移可正常生成和执行。
- MongoDB 索引创建完毕（如 `session_id`、`user_id` 等查询字段）。
- TimescaleDB 超表创建成功，可插入时序数据并查询。
- 单元测试覆盖 Repository 的关键方法。

## 阶段 2：基础服务层（模型网关 + RAG 引擎初版）

**目标**：实现 LLM 统一调用网关和基础的检索增强生成管道，能完成“简单对话 + 知识库检索”的闭环。

**任务清单**：

- [ ] **模型网关（Model Gateway）**：
  - 实现 `/v1/chat/completions` 接口（兼容 OpenAI 格式）。
  - 实现模型路由器：按任务类型（`simple_chat`, `knowledge_qa`）选择主模型（DeepSeek-V3）和备选（Claude Haiku）。
  - 集成异步 HTTP 客户端（httpx），支持流式输出（SSE）。
  - 实现 Token 用量统计和计费（记录到 TimescaleDB）。
  - 支持 Prompt 模板管理（从 PostgreSQL 加载，Redis 缓存）。
- [ ] **RAG 引擎（初版）**：
  - 实现文档预处理流水线：支持 PDF、TXT、Markdown 文件解析（PyMuPDF + unstructured），按语义分块（chunk_size=512，overlap=64）。
  - 集成 Milvus：创建 collection，定义 schema（id, text, embedding, metadata）。
  - 实现双路检索：稠密向量（使用 `text-embedding-3-large` 或本地 BGE） + BM25（使用 `pyserini` 或 elasticsearch 轻量版）。
  - 实现重排序（bge-reranker-v2-m3），返回 Top-5。
  - 实现上下文融合和答案生成（带引用标注）。
- [ ] 编写 RAG 测试用例：上传测试文档，查询相关片段，验证检索召回率和生成质量。

**验收标准**：

- 可通过 API 调用 LLM（如 DeepSeek）并返回流式响应，Token 统计正确。
- 上传一份船舶规范 PDF（如 CCS 片段），能通过 RAG 接口正确检索并回答相关问题，回答中附带 `[来源: ...]` 引用。
- 检索耗时 < 500ms（不含 LLM 生成），首 Token < 1s。
- 所有外部模型密钥通过环境变量或 Vault 管理，不硬编码。

## 阶段 3：编排层与基础智能体

**目标**：实现意图识别、任务规划、会话状态管理（FSM），以及“项目经理 Agent”和“审查 Agent”两个基础智能体。

**任务清单**：

- [ ] **意图识别模块**：
  - 实现规则引擎（关键词/正则匹配）和 LLM 分类器（调用轻量模型，如 Qwen2.5-7B 本地部署）。
  - 定义意图类型：`chitchat`, `knowledge_query`, `tool_call`, `professional_task`, `sub_agent_orchestration`。
  - 置信度阈值逻辑：规则命中且 >0.85 直接路由，否则递升 LLM。
- [ ] **任务规划模块**：
  - 实现 DAG 任务解析器：将用户输入分解为步骤（依赖关系、并行、超时）。
  - 实现 ReAct + CoT 提示模板，生成标准化任务描述 `{step_id, action, inputs, ...}`。
  - 实现任务执行引擎（Celery 驱动），支持步骤级重试和回滚。
- [ ] **会话状态机（FSM）**：
  - 使用状态机库（如 `transitions`）实现文档中定义的状态转换（IDLE → PARSING → … → COMPLETED）。
  - 实现超时管理（30min 空闲自动归档）、错误状态处理。
  - 将状态持久化到 Redis（TTL 30min）。
- [ ] **智能体基础框架**：
  - 定义 `BaseAgent` 协议（含 `metadata`, `handle_task`, `health_check`）。
  - 实现 **PM Agent**：负责任务分解、资源分配、进度聚合。
  - 实现 **Review Agent**：调用规范审查工具（`reg_check`），输出合规结果。
  - 实现智能体注册中心（使用 Nacos，或轻量级内存注册表供开发）。
- [ ] 实现编排层对外 API（`/chat` 和 `/task/{task_id}/status`），支持同步和异步模式。

**验收标准**：

- 输入“帮我查一下 CCS 对舱壁的要求”，意图识别为 `knowledge_query`，并正确路由到 RAG 引擎。
- 输入“请审查这份型值表是否符合规范”，PM Agent 能分解 DAG（解析→检索规范→审查），并派发子任务给 Review Agent 和 Naval Arch Agent（可先 mock）。
- 会话状态机可正确流转，超时后自动归档。
- Celery 任务可正常执行，并返回结果。

## 阶段 4：前端与多端交互层

**目标**：构建 Web 客户端（SPA），实现用户登录、对话界面、任务进度展示、知识库文件管理。

**任务清单**：

- [ ] 使用 React 18 + TypeScript + Ant Design 初始化前端项目。
- [ ] 实现路由和布局（侧边栏+主内容区）。
- [ ] 实现用户认证页面（登录/注册）和 JWT 管理（存 localStorage）。
- [ ] **对话页面**：
  - 支持 Markdown 渲染（含代码高亮、公式、表格）。
  - 集成 WebSocket，实时接收流式输出和任务进度。
  - 支持上传附件（型值表、PDF 等）。
  - 显示消息引用来源（点击可展开规范原文）。
- [ ] **知识库管理页面**：上传、浏览、搜索知识库文件，展示文件状态（已索引/待索引）。
- [ ] **任务中心页面**：展示进行中的任务列表及状态、进度条。
- [ ] 状态管理：使用 Zustand 管理全局状态（用户、会话、UI），TanStack Query 管理服务端缓存。
- [ ] 实现离线缓存策略（Service Worker + IndexedDB，缓存最近访问文档）。
- [ ] 配置代理（开发环境代理到后端 API）。

**验收标准**：

- 用户可以登录并正常对话，WebSocket 连接稳定。
- 流式输出逐字显示，引用来源可点击。
- 上传 PDF 文件后，在知识库页面可见，且可触发索引。
- 任务进度实时更新（通过 WebSocket 推送）。
- 前端打包后（`npm run build`）可部署到 Nginx。

## 阶段 5：完整智能体与工具集成

**目标**：实现文档中列出的所有业务智能体和工具（除低优先级外），完成多智能体协同闭环。

**任务清单**：

- [ ] 实现以下智能体（按优先级 P0→P1）：
  - Naval Arch Agent（型线设计、稳性计算、船型改造）
  - CAD Agent（图纸解析、型线绘制，先与 LibreCAD 或模拟接口）
  - Research Agent（文献检索、每日简报生成）
  - Doc Agent（报告排版、PDF 生成）
  - （可选）SW Engineer Agent、Embedded Agent
- [ ] 实现对应工具（文档 **2.4.5 工具库** 中列出的所有工具）：
  - `reg_check`, `cad_draw`, `hydrostatics`, `stability`, `resistance`, `hull_transform`, `report_gen`, `xlsx_parser`, `pdf_parser`, `web_search`, `ocr_engine`, `dwg_converter`, `todo_manager`。
- [ ] 为每个工具编写单元测试和集成测试（模拟外部依赖）。
- [ ] 实现工具热插拔机制：工具注册、发现、健康检查、降级。
- [ ] 完善多智能体协同示例（如规范审查+图纸绘制联合任务），验证完整的 DAG 执行。
- [ ] 集成外部系统（如 AutoCAD 通过 MCP 协议，或先用模拟器）。
- [ ] 实现 Web 端“子代理编排”的可视化（显示 DAG 图，可选）。

**验收标准**：

- 用户可通过对话触发“稳性计算并生成报告”，完整执行流程（解析型值表→静水力→稳性→报告生成），耗时 < 120s。
- 规范审查+图纸绘制联合任务可成功生成带违规标注的审查报告 PDF。
- 所有工具均可通过统一接口调用，并记录调用日志和耗时。
- 工具注册/注销时，系统能动态感知（无需重启）。

## 阶段 6：可观测性、安全与部署

**目标**：完善监控、日志、链路追踪，实施安全加固，完成生产级部署配置。

**任务清单**：

- [ ] **可观测性**：
  - 集成 OpenTelemetry：为 FastAPI 服务添加自动埋点（`opentelemetry-instrumentation-fastapi`）。
  - 部署 Jaeger 用于链路追踪，Prometheus + Grafana 用于指标采集和看板。
  - 实现文档 **5.3** 中的主看板（Token 消耗、工具调用 Top10、智能体任务数等）。
  - 配置日志聚合（ELK 或 Loki+Promtail），实现分布式追踪 ID 注入日志。
- [ ] **安全**：
  - 实现 RBAC（Casbin）：定义角色（Admin, Project Lead, Engineer, Guest, API User）及权限策略。
  - 实现 API Key 管理（用于第三方集成），支持 HMAC-SHA256 签名。
  - 实现文件访问预签名 URL（MinIO），有效期 15 分钟。
  - 启用 TLS（自签名证书或 Let's Encrypt），内部通信使用 mTLS（可选）。
  - 实现 SQL 注入防护（ORM 自动参数化）、XSS/CSRF 防护。
  - 配置审计日志（所有操作记录到 TimescaleDB，保留 1 年）。
- [ ] **部署**：
  - 编写 K3s 部署清单（Deployment、Service、Ingress、PersistentVolumeClaim）。
  - 配置 CI/CD 流水线（GitLab CI 或 GitHub Actions）：构建镜像 → 运行测试 → 推送到 Harbor → 滚动更新到 K3s。
  - 编写生产环境配置（资源限制、副本数、健康检查探针）。
  - 实现数据库备份脚本（每日全量 + WAL 归档）。
- [ ] 编写部署文档（包含环境变量、端口、依赖服务地址）。

**验收标准**：

- Grafana 看板可正常展示各项指标，Jaeger 可追踪任意一个完整请求的 Span。
- 不同角色用户登录后，可访问资源符合权限设定（如 Guest 无法调用工具）。
- 文件下载使用预签名 URL，有效期内可访问，过期后拒绝。
- 滚动更新时服务不中断（零停机）。
- 所有服务健康检查通过，K3s 集群稳定运行 24 小时。
